# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo. See `docs/guides/README.md` for the docs index (start with `docs/design/shacl/implementation-plan.md`).

## Rules that bite

- **There is one engine.** `starlayer.shacl` is a thin public layer (`validator.py`, `_adapter.py`) over the native SHACL 1.2 engine in `starlayer/shacl/engine/`; nothing here imports pySHACL, and pySHACL is not a dependency. The engine follows the SHACL 1.2 drafts (Core, SPARQL Extensions, Node Expressions, Inference Rules), not SHACL-AF (2017) or pySHACL extensions: where an old test or habit disagrees, check the draft, and record a deliberate deviation in `docs/working/shacl-engine-differential.md`. Design: `docs/working/shacl-engine-design.md`.
- **Shape of the API.** Everything an application needs is importable from `starlayer.shacl` (see `__init__.py`): `validate`, `validate_each`, `apply_rules`, `evaluate`, `target_nodes`, `candidate_values` (what a form can offer for a property shape's field: the `sh:in` / `sh:hasValue` / `sh:class` / `sh:rootClass` values, optionally only those that keep the shape conforming), `value_form(shapes, property_shape)` (`"single"`, `"list"` or `"single-or-list"`, read from the property shape's own list constraints, `sh:node` / `sh:and` / `sh:or`) and `check_value(shapes, property_shape, focus, value, data)` (a `ValueCheck(conforms, results)`: would the value be accepted for that field of that node, by that property shape only and not the shapes-about-shapes layer), `form_model(shapes, data, node, role=, shapes=, empty=, suggestions=, report=, ...)` (a `FormModel`: the fields of a node's form joined from the answers above, merged by `sh:path` over the shapes that target the node, with per-value source and editability; the data suggests, only a `report` you pass gives `errors`, nothing is validated; `FormField.check(value)` is `check_value`), `extract_subgraph`, `derive_shape`, `StarShaclProcessor`, report analysis (`ValidationReport.results` / `for_node` / `for_field` / `node_level` / `counts()` / `deduplicated()`, `report_results(report_graph)`, `diff_reports(old, new)`: read the report through these, not the graph), the result types, the errors (`ShapeError`, `RuleError`, `MetaShaclError`, `EvaluationFailure`), `meta_validate` / `meta_scope` / `MetaScope` (`meta_validate(shapes, add=, remove=, nodes=)` checks a proposed edit on a copy and reports only the covered nodes; `meta_scope` says which and why), `evaluate_expression`, `node_expression_functions`, `infer_types`, `path_values`, `select_widgets` and the other helpers. **Apps do not import submodules.** If an app needs something only a submodule has, add a public component and say so in `docs/working/workbench-api-needs.md`; do not leave a shim at an old path.
- **Terms are pyoxigraph terms; graphs are `StarLayerGraph`s.** `validate`, `evaluate`, `apply_rules`, `extract_subgraph` and the other entry points take pyoxigraph terms (`starlayer.graph.Namespace`, `starlayer.shacl.SH`) and refuse an rdflib term or an rdflib `Graph` with a `TypeError` naming `StarLayerGraph.from_rdflib`.
- **A dataset is its union.** SHACL validates one data graph; `validate` (and `evaluate`, `apply_rules`) sees a `StarLayerDataset` as the union of all its graphs whatever its own `default_union` says, as pySHACL does (`terms._union_view`). `validate_each(dataset)` validates the graphs one by one and takes only a `StarLayerDataset` (or a `pyoxigraph.Store`, wrapped as one); keys: graph names, `None` for a default graph that holds triples. A list, mapping, generator or single graph is a `TypeError` naming `dataset` (decision 2026-11-24, no alias): add the graphs to a dataset, one per name, or call `validate()` for one graph. `extract_subgraph` and `relevant_subgraph` refuse a dataset (`TypeError`): a fragment would not say which graph a triple came from; pass one graph or `dataset.to_graph()`.
- **SHACL Advanced Features constructs that 1.2 dropped are errors, not no-ops.** `sh:target`, `sh:SPARQLTarget`, `sh:SPARQLTargetType` and `sh:SPARQLFunction` in a shapes graph raise `ShapeError` (`shacl/engine/plan.py::reject_removed_constructs`; SPARQL-Related Features Appendix F). The W3C vocabulary file still lists them, so the vocabulary cannot be used to detect them. A node-expression target (`sh:targetNode [ sh:select ... ]`) and `sh:ListParameterExpressionFunction` replace them. Unknown properties in other namespaces (for example `dash:`) are ignored, as SHACL says: DASH is not supported and its constraints are not checked.
- **Options are a closed set.** `validate()` and `apply_rules()` take the named parameters plus the options listed in `_adapter.VALIDATE_OPTIONS` (`inference`, `engine`, `timeout`, `recompute`, `inplace`, `meta_shacl`, `rules`, `allow_warnings`, `allow_infos`, `abort_on_first`, `max_validation_depth`, `subclass_of_in_shapes_graph`; `apply_rules` also `max_iterations`, `max_triples`). Anything else is a `TypeError`. On a `StarShaclProcessor`, `inference=` is bound at construction as the default and `validate()`, `validate_each()`, `apply_rules()`, `evaluate()` and `target_nodes()` take it per call: a call's value REPLACES the constructor's regime(s) (not merged), `inference=None` or an empty iterable means no regime of the call's own, not given (private `_UNSET`, `<not set>`) means the constructor's; the shapes graph's `sh:entailment` applies in every case. The kept entailed copy is keyed by the set of regimes, so alternating regimes keep one entry each (at most 4 per store). Also on a processor, the options that describe the shapes graph or are safety limits can also be bound at construction and are overridden per call: `allow_warnings`, `allow_infos`, `meta_shacl`, `max_validation_depth`, `engine`, `timeout`, `recompute`, `subclass_of_in_shapes_graph` (validation passes, including the final one of `apply_rules()`; the last also for the rules' class targets), `meta_shapes_extra`, `ignore_imports`, `shapes_graph_loader` (how the shapes graph is read, `validate()` and `apply_rules()`), `max_iterations`, `max_triples` (`apply_rules()` only). Precedence, lowest first: built-in default, constructor, `mode=` preset, call keyword; `validator._CONSTRUCTOR_OPTIONS` lists them. `None` is a real value for `max_validation_depth` (no bound), `max_triples` (no cap) and a call's `shapes_graph_loader` (no loader), so those use the private `validator._UNSET` (shown as `<not set>`) for "not given", and the named parameters of `StarShaclProcessor.validate()` default to it; for the others `None` at construction is not set. A `mode=` preset names only what it changes (no `meta_shacl: False`, no `inplace: False`), or it would undo a constructor value. `target_nodes()` takes `subclass_of_in_shapes_graph`, `engine`, `timeout`, `recompute` (call keyword, else the constructor value); `evaluate()` takes `inference=` (per call, as above) and `engine`, `timeout`, `recompute`, and none of the other options or defaults; `select_widgets()`, `close_shape()` and `extract_shapes_graph()` never took these options and use none of the defaults. `subclass_of_in_shapes_graph` (SHACL 1.2 Core "Graph for rdfs:subClassOf Triples", default `False`) makes `rdfs:subClassOf` for `sh:class`, `sh:targetClass`, implicit class targets, `sh:rootClass` and `shnex:instancesOf` come from the data view plus the shapes graph, `rdf:type` from the data view only (`Context.superclasses_of` / `subclasses_of`, no graph copied); `inference=` entailment is unchanged (data and ontology graph only), and `extract_subgraph()` / `evaluate()` do not take it. `rules=` is the engine's switch (`None`: run rules only when the shapes declare `sh:entailment`; `True`: always; `False`: never); `advanced=` is deprecated (a `DeprecationWarning`: `advanced=False` meant `rules=False`, `advanced=True` nothing; with both, `rules` wins). `mode=` is an option preset (`validation_modes.py`), not a SHACL Profile: "Profile" means only the SHACL 1.2 Profiling spec (`profiling`).
- **Results.** `ValidationReport`; `RulesResult(inferred_graph, validation)`, where `inferred_graph` is only what the rules produced (plus `sh:sourceRule` reifiers on request) and the caller's data is never touched; `evaluate()` and `extract_subgraph()` return a plain graph. Result messages are processor-defined: the report graph carries the engine's default wording unless the shape (or the constraint's reifier) has a `sh:message`, and `report_text` shows nested `sh:detail` results.
  Default message conventions (`shacl/engine/text.py`, `generic_message`): built from the result's structured fields (component, path, value) and the shape's parameter value, never parsed back by callers (the report row keeps `sh:sourceConstraintComponent`, `sh:resultPath`, `sh:value`, `sh:sourceShape`; read those, not the text). One sentence, no final period, no `a->b` path notation: a value constraint reads `Value <value> should <expectation>` (`should be at least 5`, `should have the datatype xsd:integer`, `should be an IRI`, `should be one of 1, 2`); a count constraint reads `Needs at least <n> value(s) for <path>` / `Allows at most <n> value(s) for <path>`, with the singular only for exactly 1; a blank-node value is `A blank node value` (its label means nothing; a shape is never named by a label either: an inline shape reads `[ sh:class ex:Duck ]`, a list `( a b )`, a path `ex:p/ex:q`, via `text.Words`); a union (list form) of sh:class, sh:datatype, sh:nodeKind reads `one of ...` / `an IRI or a literal`, repeated parameter values are a conjunction and each failed one gets its own message naming only that one; what only the run knows (list length, which member, the other value of a pair, the reifier) is worded by the component through `registry.words(ctx)` and `Violation(message=...)`, and the generic wording returns `None` for it; terms are prefixed names, literals are quoted (bare for numbers). `report_text` abbreviates each term with the prefixes of the graph it belongs to, then of the other one (data, then shapes, for a data term; the reverse for a shape term), by namespace, so a prefix name bound to two namespaces is never mixed up; the report graph's `sh:resultMessage` is written separately, from one graph's prefixes, and is not changed by this. W3C conformance does not compare message text.
- **Entailment uses the graph package's IRIs** (`inference=ENTAILMENT.RDFS`, or `sh:entailment` in the shapes). The old string names (`"rdfs"`, `"owlrl"`) are rejected on purpose. Every regime (RDF, RDFS, OWL-RDF-Based, OWL-Direct) uses the entailed COPY of the data's store that `graph/entailment/cache.py` keeps once per store and shares with SPARQL `query(entailment=...)`: the OWL regimes are the same entry in both (run in one, found by the other), while SPARQL's RDF and RDFS are the query rewrite (no copy, never read or made there) and SHACL's are a copy, because the engine reads through triple lookups, not SPARQL text (a rewritten lookup measured about 3 to 6 ms against 4 microseconds). The key is the SET of regimes (`declared_regimes(shapes) | normalise_regimes(inference)`), the engine (OWL-Direct), and the ontology graph; invalidation is the write count of the store only (`union.version_of(store).stamp()`): a write made through the package invalidates, a raw store write needs `union.touch()` (no content fingerprint is taken any more), and the report graph does not touch the data store. `recompute=` (`"onChange"` default, `"never"`, `"always"`, as `query()`), `engine=` and `timeout=` (OWL-Direct only, a `ValueError` for a set without it).  `OWL-Direct` combines with the other regimes (a processor `inference=OWL-Direct` plus `sh:entailment RDFS` in the shapes, as Core 1.4 requires all declared regimes): the entry holds the entailments of every regime in the set, and the others also see what OWL-Direct inferred (`infer._delta_for`: Direct delta first, then the rest over data plus that delta; not a fixpoint over all regimes, what RDFS/OWL-RL derive is not fed back to the DL reasoner). `engine=`/`timeout=` stay a `ValueError` for a set without OWL-Direct. `recompute=`, `engine=` and `timeout=` are options like `subclass_of_in_shapes_graph` (constructor default, per-call override; `validator._VALIDATION_DEFAULTS`; also `evaluate()` and `target_nodes()`). `ont_graph` is visible to the reasoner and not stored in the copy. Nothing may write to the copy: rules write to an overlay on top of it (`rules.new_overlay`), `inplace=True` writes back to the caller's graph (which invalidates). `clear_entailment_cache()` on the data graph clears these copies too. A view that is not a store of its own (the rules overlay, in the final pass of `apply_rules()`) is closed uncached (`engine/entailment.py::entailed_view`).
- **Ill-formed shapes raise `ShapeError`** (a `sh:NodeShape` with `sh:path`, a `sh:property` value without `sh:path`, a list expression member that is a node expression, a malformed regex, a constraint parameter of the wrong kind such as `sh:minCount "many"` ...), rule problems `RuleError`. **A `StarShaclProcessor` raises them when it is built**, not at the first `validate()`: with a `shacl_graph` the constructor compiles the plan (`Plan.compile()`, kept and reused by `validate()`; the module-level `validate()` and `apply_rules()` compile per call). The parameters are checked through the `check=` hook of `@component(...)` (`ComponentSpec.check(shapes, shape, params)`: reads the parameters with the helpers the component's function uses, returns the shape nodes they refer to); a new component that reads a parameter registers one. Still evaluation-time: node expressions, SPARQL query text, the validators of SPARQL-based components, target expressions, and anything that needs the data. SPARQL in shapes declares prefixes only with `sh:declare` / `sh:prefixes`; there is no ambient lookup. The legacy SHACL-AF forms (a bare `sh:path` as an expression, untyped rules, `sh:filterShape`, SPARQL-based targets) are not supported: use `shnex:pathValues`, typed rules, `shnex:filterShape`. `sh:this` is accepted as an ordinary IRI (a constant, not the focus node) and the meta-shapes warn about it: write `[ shnex:var "focusNode" ]`.
- **`meta_shacl` is off by default.** Bound at construction (`StarShaclProcessor(meta_shacl=True)`) it runs once there, before the compile (`MetaShaclError` from the constructor), and `validate()` does not repeat it (`_adapter.CheckedShapes` keeps the result per shapes-graph fingerprint, so a call's `meta_shacl=True` on any processor is also run once per unchanged graph; `meta_shacl=False` on a call is allowed). The meta-shapes are built, not assembled at run time: edit `packages/starlayer/starlayer/starontology/_sources/shacl12-validation-shapes.ttl`, run `python scripts/build.py`, and the library reads the stored `starontology/shacl/shacl12-shacl.ttl`. A test fails if the stored file drifts from a fresh build. **The base is the W3C Working Group's own SHACL-for-SHACL, pinned in `packages/starlayer/starlayer/starontology/_sources/vendor/` and only ever added to** (never delete or edit its triples; relax a rule with `sh:deactivated true` and put the replacement in the asset). The shipped rules (`starontology/shacl/shacl12-shacl-rules.ttl`) are SHACL 1.2 rules and run on the engine. **Layering:** `shacl_shacl` is standard SHACL and standard SPARQL only, so any SHACL 1.2 processor can run it. The two checks about the text of a literal (an invalid `sh:pattern` / `sh:flags`, and the SPARQL text of `sh:select` / `sh:ask` / `sh:construct` / `shui:searchQuery`) are `sh:sparql` shapes that ask StarLayer-internal SPARQL functions (`engine/builtin_functions.py`; not part of the public API); they are in the hand-edited, private layer `shacl_shacl_starlayer` (`starontology/shacl/shacl12-shacl-starlayer.ttl`; not in the `starontology` registry, loaded by `starontology._load_private`), which `load_meta_shapes_graph()` merges in. Their results are ordinary ones (`sh:sourceShape` is `stsh:RegexShape` or `stsh:SPARQLQueryTextShape`, the component `sh:SPARQLConstraintComponent`), and `sh:deactivated true` in a `meta_shapes_extra` graph switches them off. **Scoped check (`engine/meta_scope.py`):** `meta_validate(add=, remove=, nodes=)` keeps the whole graph visible and only filters the focus nodes after the meta-shapes' targets are resolved (`validate(focus_filter=)`), so its floor is the target scan (about 85 ms on 2000 node shapes, mostly the unknown-term shape's SPARQL target); an edit whose triples match `FULL_CHECK_TRIGGERS` (prefix declarations, components, parameters, templates, `rdf:type`, `rdfs:subClassOf` on a node the graph already has) is checked in full; a type or subclass triple on a fresh subject (a new shape or class, typed with none of the risky classes) is local and reported as "N new" on the graph after the edit.
- **`owl:imports` that are not already in the shapes graph raise** in `validate()` unless you pass a loader (`shapes_graph_loader=`) or `ignore_imports=True`. Nothing is fetched on its own. A processor checks at construction with its own loader / `ignore_imports`; unsatisfied imports with neither skip the eager check (a call may bring a loader) and raise at `validate()` as before.
- **`shapes_graph_resource=`** selects a named `sh:ShapesGraph` module of the bound shapes graph (its IRI becomes `sh:usedShapesGraph`), or is only a provenance tag when the graph does not contain it. With no bound shapes graph it raises. **Provenance has one form (2026-11-23)**: a blank `sh:ValidationActivity` that `prov:generated` the report carries `sh:usedDataGraph`, `sh:usedShapesGraph`, `sh:usedConfiguration` and `prov:wasAssociatedWith` the `sh:ValidationAgent` (the StarLayer IRI of the conformance declaration); the report node has none of them (`engine/report.py::annotate_provenance`, read by `engine/text.py` and `profiling/profiles.py`). No timestamps.
- **A passing test is not proof.** Check that a fixture would fail on the behaviour you changed; for meta-shapes, check that a malformed value is rejected, not only that a valid one passes. The W3C suites run through `tests/shacl/w3c_shacl12/` (engine runners: `test_w3c_engine_*.py`; deviations from a fixture are asserted, not skipped).
- **The six SHACL 1.2 documents are all still moving.** Status and procedure: `docs/design/shacl/shacl12-gap-matrix.md`, "Tracking Upstream Spec Changes".

## Design history

The dated log of the pySHACL-backed validator (its monkeypatches, the triple-term adapter, `native_components`, and the fixes made to it, 2026-10-06 to 2026-10-30) is archived in `docs/working/archive/shacl-claude-md-pyshacl-era.md`; the code it describes was replaced by the engine (`docs/working/archive/shacl-engine-cutover.md`). Decisions that still hold and live in the code they describe:

- **Shape typing is a rule set** (`shape_types.infer_types()`, `starontology/shacl/shacl12-shacl-rules.ttl`): a shape need not carry `rdf:type` (Core 3.1 to 3.3).
- **Widget selection** (`ui/widget_selection.py`) follows SHACL UI 4.3: a widget a shape names is scored, and `shui:defaultWidgetScore` is read; `select_widgets(per="shape")` answers once per property shape.
- **`extract_subgraph()`** is the shape fragment of the Shape Fragments paper; the Conformance Theorem is its contract (`subgraph_extraction.py`, module docstring).
- **`derive_shape(graph, cls=... | node=...)`** (`derive.py`) is a StarLayer feature, not SHACL: one closed node shape for a class (all instances, subclasses by default) or for one node, as a new graph, named `ex:PersonShape` / `ex:AliceShape` unless `shape=` says otherwise. A `template_shape` is scoped to the one shape that targets the same class or node (the other template shapes are not copied). It validates its result before returning, so it lives here and not in the graph package; the output has no randomness (blank node ids are computed).
- **`sh:targetWhere`** validates the where-shape only and may target literals; `sh:targetNode` takes a node expression (evaluated with the shape as focus node, Core 3.1.3.1).
- **`StarShaclProcessor` binds** a shapes graph (and optional ontology, data and scoring graph) at construction, not per call; the entailment regime is bound at construction as a default and a call's `inference=` replaces it for that call (2026-11-22; it was a `TypeError` before, `evaluate()` included). The options listed under "Options are a closed set" (severity, `meta_shacl`, imports, depth, `subclass_of_in_shapes_graph` and rule limits) are different: bound at construction as defaults, and a call can override them. The shapes graph is checked and compiled at construction and again when `shacl_graph` is assigned (a bad one leaves the processor as it was); a graph edited in place is fingerprinted at each `validate()` and re-read if it changed, so the error then comes from `validate()`.
