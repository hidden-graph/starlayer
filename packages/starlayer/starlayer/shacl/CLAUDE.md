# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo. See `docs/guides/README.md` for the docs index (start with `docs/design/shacl/implementation-plan.md`).

## Rules that bite

- **There is one engine.** `starlayer.shacl` is a thin public layer (`validator.py`, `_adapter.py`) over the native SHACL 1.2 engine in `starlayer/shacl/engine/`; nothing here imports pySHACL, and pySHACL is not a dependency. The engine follows the SHACL 1.2 drafts (Core, SPARQL Extensions, Node Expressions, Inference Rules), not SHACL-AF (2017) or pySHACL extensions: where an old test or habit disagrees, check the draft, and record a deliberate deviation in `docs/working/shacl-engine-differential.md`. Design: `docs/working/shacl-engine-design.md`.
- **Shape of the API.** Everything an application needs is importable from `starlayer.shacl` (see `__init__.py`): `validate`, `validate_each`, `apply_rules`, `evaluate`, `target_nodes`, `candidate_values` (what a form can offer for a property shape's field: the `sh:in` / `sh:hasValue` / `sh:class` / `sh:rootClass` values, optionally only those that keep the shape conforming), `value_form(shapes, property_shape)` (`"single"`, `"list"` or `"single-or-list"`, read from the property shape's own list constraints, `sh:node` / `sh:and` / `sh:or`) and `check_value(shapes, property_shape, focus, value, data)` (a `ValueCheck(conforms, results)`: would the value be accepted for that field of that node, by that property shape only and not the shapes-about-shapes layer), `form_model(shapes, data, node, role=, shapes=, empty=, suggestions=, report=, ...)` (a `FormModel`: the fields of a node's form joined from the answers above, merged by `sh:path` over the shapes that target the node, with per-value source and editability; the data suggests, only a `report` you pass gives `errors`, nothing is validated; `FormField.check(value)` is `check_value`), `extract_subgraph`, `derive_shape`, `StarShaclProcessor`, report analysis (`ValidationReport.results` / `for_node` / `for_field` / `node_level` / `counts()` / `deduplicated()`, `report_results(report_graph)`, `diff_reports(old, new)`: read the report through these, not the graph), the result types, the errors (`ShapeError` and `ExecutionError`, each one class with a `kind`), `meta_validate` / `meta_scope` / `MetaScope` (`meta_validate(shapes, add=, remove=, full=False)` returns a conforming `ValidationReport` (the object `validate()` returns, not iterable, no tuple) or raises `ShapeError` kind `"meta"`; the same holds for `validate_sparql_tree`, `validate_sparql_tree` and `validate_manchester_tree` (decision 2026-11-25): `add` / `remove` check a proposed edit before it is made, the library picks the narrow or the whole-graph check itself, `full=True` forces the whole graph; `meta_scope(shapes, add=, remove=, full=False)` says which nodes that covered and why, `ShapeError.scope` (kind `"meta"`) is the same), `evaluate_expression`, `node_expression_functions`, `infer_types`, `path_values`, `select_widgets` and the other helpers. **Apps do not import submodules.** If an app needs something only a submodule has, add a public component and say so in `docs/working/workbench-api-needs.md`; do not leave a shim at an old path.
- **Terms are pyoxigraph terms; graphs are `StarLayerGraph`s.** `validate`, `evaluate`, `apply_rules`, `extract_subgraph` and the other entry points take pyoxigraph terms (`starlayer.graph.Namespace`, `starlayer.shacl.SH`) and refuse an rdflib term or an rdflib `Graph` with a `TypeError` naming `StarLayerGraph.from_rdflib`.
- **A dataset is its union.** SHACL validates one data graph; `validate` (and `evaluate`, `apply_rules`) sees a `StarLayerDataset` as the union of all its graphs whatever its own `default_union` says, as pySHACL does (`terms._union_view`). `validate_each(dataset)` validates the graphs one by one and takes only a `StarLayerDataset` (or a `pyoxigraph.Store`, wrapped as one); keys: graph names, `None` for a default graph that holds triples. A list, mapping, generator or single graph is a `TypeError` naming `dataset` (decision 2026-11-24, no alias): add the graphs to a dataset, one per name, or call `validate()` for one graph. `extract_subgraph` and `relevant_subgraph` refuse a dataset (`TypeError`): a fragment would not say which graph a triple came from; pass one graph or `dataset.to_graph()`.
- **SHACL Advanced Features constructs that 1.2 dropped are errors, not no-ops.** `sh:target`, `sh:SPARQLTarget`, `sh:SPARQLTargetType` and `sh:SPARQLFunction` in a shapes graph raise `ShapeError` kind `"compile"` (`shacl/engine/plan.py::reject_removed_constructs`; SPARQL-Related Features Appendix F). The W3C vocabulary file still lists them, so the vocabulary cannot be used to detect them. A node-expression target (`sh:targetNode [ sh:select ... ]`) and `sh:ListParameterExpressionFunction` replace them. Unknown properties in other namespaces (for example `dash:`) are ignored, as SHACL says: DASH is not supported and its constraints are not checked.
- **Options are a closed set.** `validate()` takes the named parameters plus the options listed in `_adapter.VALIDATE_OPTIONS` (`inference`, `engine`, `timeout`, `recompute`, `inplace`, `meta_shacl`, `rules`, `allow_warnings`, `allow_infos`, `abort_on_first`, `subclass_of_in_shapes_graph`); `apply_rules()` takes the ones that rule execution uses, `_adapter.RULES_OPTIONS` (`inference`, `engine`, `timeout`, `recompute`, `subclass_of_in_shapes_graph`, `meta_shacl`, `meta_shapes_extra`, `ignore_imports`, `imports_loader`, `max_iterations`, `max_triples`). Anything else is a `TypeError`; for `apply_rules()` an option that only describes a validation (`allow_warnings`, `allow_infos`, `abort_on_first`, `inplace`, `rules`, the report's provenance keywords) gets a message that says it belongs to `validate()` (decision 2026-11-24: `apply_rules()` validates nothing, no alias). On a `StarShaclProcessor`, `inference=` is bound at construction as the default and `validate()`, `validate_each()`, `apply_rules()`, `evaluate()` and `target_nodes()` take it per call: a call's value REPLACES the constructor's regime(s) (not merged), `inference=None` or an empty iterable means no regime of the call's own, not given (private `_UNSET`, `<not set>`) means the constructor's; the shapes graph's `sh:entailment` applies in every case. The kept entailed copy is keyed by the set of regimes, so alternating regimes keep one entry each (at most 4 per store). Also on a processor, the options that describe the shapes graph or are safety limits can also be bound at construction and are overridden per call: `allow_warnings`, `allow_infos` (`validate()` only: the processor's values are not applied to `apply_rules()`), `meta_shacl`, `engine`, `timeout`, `recompute`, `subclass_of_in_shapes_graph` (`validate()` and `apply_rules()`; the last also for the rules' class targets), `meta_shapes_extra`, `ignore_imports`, `imports_loader` (how the shapes graph is read, `validate()` and `apply_rules()`), `max_iterations`, `max_triples` (`apply_rules()` only). `validator._RULES_DEFAULTS` lists the ones `apply_rules()` takes. Precedence, lowest first: built-in default, constructor, `mode=` preset, call keyword; `validator._CONSTRUCTOR_OPTIONS` lists them. `None` is a real value for a call's `imports_loader` (no loader), so that one uses the private `validator._UNSET` (shown as `<not set>`) for "not given", and the named parameters of `StarShaclProcessor.validate()` default to it; for the others `None` at construction is not set. **`max_validation_depth` is not an option (decision 2026-11-24, no alias):** it is an internal engine limit (`engine.api.validate(max_validation_depth=)`, default `DEFAULT_MAX_VALIDATION_DEPTH` = 500), and passing it to `validate()`, `validate_each()`, `apply_rules()` or a `StarShaclProcessor` is a `TypeError`. **`max_triples` is a public `apply_rules()` option again (decision 2026-11-25):** the cap on triples one rule run infers, default `engine.rules.DEFAULT_MAX_TRIPLES` = 5,000,000 (measured about 1.3-1.9 KB and 35 microseconds per inferred triple, so the default is about 7-9 GB and 3 minutes), `None` removes the cap, a non-int or negative value is refused (`_adapter.check_max_triples`); exceeding it is an `ExecutionError` of kind `"limit"` (decision 2026-11-26). On a processor `None` at construction is a real value (no cap; unset is `_UNSET`, `validator._NONE_IS_A_VALUE`). `max_iterations` stays public because SHACL rules, unlike SRL, are not stratified: the iteration guard (default 1000, an `ExecutionError` of kind `"limit"`) is the only protection against a rule set that never reaches a fixpoint. Package code that checks its own fixed shapes with a bound (`sqe:`, SRL, Manchester syntax: depth 100) calls `_adapter.validate_bounded`. A `mode=` preset names only what it changes (no `meta_shacl: False`, no `inplace: False`), or it would undo a constructor value. `target_nodes()` takes `subclass_of_in_shapes_graph`, `engine`, `timeout`, `recompute` (call keyword, else the constructor value); `evaluate()` takes `inference=` (per call, as above) and `engine`, `timeout`, `recompute`, and none of the other options or defaults; `select_widgets()`, `close_shape()` and `extract_shapes_graph()` never took these options and use none of the defaults. `subclass_of_in_shapes_graph` (SHACL 1.2 Core "Graph for rdfs:subClassOf Triples", default `False`) makes `rdfs:subClassOf` for `sh:class`, `sh:targetClass`, implicit class targets, `sh:rootClass` and `shnex:instancesOf` come from the data view plus the shapes graph, `rdf:type` from the data view only (`Context.superclasses_of` / `subclasses_of`, no graph copied); `inference=` entailment is unchanged (data and ontology graph only), and `extract_subgraph()` / `evaluate()` do not take it. `rules=` is the engine's switch for `validate()` (`apply_rules()` always runs the rules and refuses it) (`None`: run rules only when the shapes declare `sh:entailment`; `True`: always; `False`: never); `advanced=` is deprecated (a `DeprecationWarning`: `advanced=False` meant `rules=False`, `advanced=True` nothing; with both, `rules` wins). `mode=` is an option preset (`validation_modes.py`), not a SHACL Profile: "Profile" means only the SHACL 1.2 Profiling spec (`profiling`).
- **Results.** `ValidationReport`; `RulesResult(inferred_graph)`, where `inferred_graph` is only what the rules produced (plus `sh:sourceRule` reifiers on request) and the caller's data is never touched; `apply_rules()` validates nothing (decision 2026-11-24: the shapes that check the outcome may differ from the shapes that hold the rules), so to check it call `validate(data, shapes, rules=True)` or validate the data together with `inferred_graph` against any shapes (SRL's `RuleSet.infer(schema=)` is separate: it returns a `CheckedInferenceResult`, a `RulesResult` with a `validation`); `evaluate()` and `extract_subgraph()` return a plain graph. Result messages are processor-defined: the report graph carries the engine's default wording unless the shape (or the constraint's reifier) has a `sh:message`, and `report_text` shows nested `sh:detail` results.
  Default message conventions (`shacl/engine/text.py`, `generic_message`): built from the result's structured fields (component, path, value) and the shape's parameter value, never parsed back by callers (the report row keeps `sh:sourceConstraintComponent`, `sh:resultPath`, `sh:value`, `sh:sourceShape`; read those, not the text). One sentence, no final period, no `a->b` path notation: a value constraint reads `Value <value> should <expectation>` (`should be at least 5`, `should have the datatype xsd:integer`, `should be an IRI`, `should be one of 1, 2`); a count constraint reads `Needs at least <n> value(s) for <path>` / `Allows at most <n> value(s) for <path>`, with the singular only for exactly 1; a blank-node value is `A blank node value` (its label means nothing; a shape is never named by a label either: an inline shape reads `[ sh:class ex:Duck ]`, a list `( a b )`, a path `ex:p/ex:q`, via `text.Words`); a union (list form) of sh:class, sh:datatype, sh:nodeKind reads `one of ...` / `an IRI or a literal`, repeated parameter values are a conjunction and each failed one gets its own message naming only that one; what only the run knows (list length, which member, the other value of a pair, the reifier) is worded by the component through `registry.words(ctx)` and `Violation(message=...)`, and the generic wording returns `None` for it; terms are prefixed names, literals are quoted (bare for numbers). `report_text` abbreviates each term with the prefixes of the graph it belongs to, then of the other one (data, then shapes, for a data term; the reverse for a shape term), by namespace, so a prefix name bound to two namespaces is never mixed up; the report graph's `sh:resultMessage` is written separately, from one graph's prefixes, and is not changed by this. W3C conformance does not compare message text.
- **Entailment uses the graph package's IRIs** (`inference=ENTAILMENT.RDFS`, or `sh:entailment` in the shapes). The old string names (`"rdfs"`, `"owlrl"`) are rejected on purpose. Every regime (RDF, RDFS, OWL-RDF-Based, OWL-Direct) uses the entailed COPY of the data's store that `graph/entailment/cache.py` keeps once per store and shares with SPARQL `query(entailment=...)`: the OWL regimes are the same entry in both (run in one, found by the other), while SPARQL's RDF and RDFS are the query rewrite (no copy, never read or made there) and SHACL's are a copy, because the engine reads through triple lookups, not SPARQL text (a rewritten lookup measured about 3 to 6 ms against 4 microseconds). The key is the SET of regimes (`declared_regimes(shapes) | normalise_regimes(inference)`), the engine (OWL-Direct), and the ontology graph; invalidation is the write count of the store only (`union.version_of(store).stamp()`): a write made through the package invalidates, a raw store write needs `union.touch()` (no content fingerprint is taken any more), and the report graph does not touch the data store. `recompute=` (`"onChange"` default, `"never"`, `"always"`, as `query()`), `engine=` and `timeout=` (OWL-Direct only, a `ValueError` for a set without it). A regime NAME that is not registered (`inference="rdfs"`, D-Entailment) is `ExecutionError` kind `"unsupported"` (decision 2026-11-26), a non-text non-IRI value a `TypeError`; a `sh:entailment` of the shapes graph that names no registered regime is the same `ExecutionError` kind `"unsupported"`, context `"entailment regime"`, with the same message (`declared_regimes`; decision 2026-11-26, it was a compile error: StarLayer cannot do what the shapes ask, and the user can choose another regime).  `OWL-Direct` combines with the other regimes (a processor `inference=OWL-Direct` plus `sh:entailment RDFS` in the shapes, as Core 1.4 requires all declared regimes): the entry holds the entailments of every regime in the set, and the others also see what OWL-Direct inferred (`infer._delta_for`: Direct delta first, then the rest over data plus that delta; not a fixpoint over all regimes, what RDFS/OWL-RL derive is not fed back to the DL reasoner). `engine=`/`timeout=` stay a `ValueError` for a set without OWL-Direct. `recompute=`, `engine=` and `timeout=` are options like `subclass_of_in_shapes_graph` (constructor default, per-call override; `validator._VALIDATION_DEFAULTS`; also `evaluate()` and `target_nodes()`). `ont_graph` is visible to the reasoner and not stored in the copy. Nothing may write to the copy: rules write to an overlay on top of it (`rules.new_overlay`), `inplace=True` writes back to the caller's graph (which invalidates). `clear_entailment_cache()` on the data graph clears these copies too. `entailed_view` takes a store-backed graph only (the rules overlay is built on top of the entailed copy, never entailed itself).
- **The error classes live in `starlayer/errors.py`** (a leaf module, standard library only, so it is in no import cycle), under the library base `StarLayerError(Exception)`: `ShapeError`, `ExecutionError` (with `only_kind`, which takes any of the three kinded classes), and `FormatError` for malformed text outside SHACL (SPARQL, SRL, RDF, terms, Manchester, OWL). The scheme and how to choose are in `AGENTS.md`. `starlayer.shacl` and `starlayer.shacl.errors` re-export the same objects (that is the public path; `engine/plan.py` and `engine/meta.py` define none, and the engine imports them from `starlayer.errors`). **None is a `ValueError` (decision 2026-11-25):** a plain `ValueError` is only a bad argument, so an `except ValueError` around a call that can raise `ShapeError` (for example a helper that wraps the XPath-regex translation, `core_string_pair._compile`) must name `ShapeError` too. `tests/repo/test_error_scheme.py` pins the tree, the leaf imports and the same-object re-exports.
- **Ill-formed shapes raise `ShapeError` kind `"compile"`** (a `sh:NodeShape` with `sh:path`, a `sh:property` value without `sh:path`, a list expression member that is a node expression, a malformed regex, a constraint parameter of the wrong kind such as `sh:minCount "many"` ...), a rules graph that is not well formed or a rule that cannot be read, and an `owl:imports` that cannot be resolved. **Errors are classified by cause (decision 2026-11-25), not by when they are raised:** `ShapeError` is one class: a wrong shapes graph or setup, found by anyone, at construction or later in a run. `error.kind` (a key of `ShapeError.KINDS`, required) is `"compile"` (the engine cannot read or compile it; every `raise` in the engine is this) or `"meta"` (the meta check found it; the only one with `problems`, `report_text`, `report_graph`, `scope`). `except ShapeError` catches both and `only_kind(error, "meta")` tells them apart; `ExecutionError` is the shapes graph being fine and running it failing, not a `ShapeError` (so `except ShapeError` for a wrong shapes graph does not catch it). It is ONE class; `error.kind` says what failed: `"rule"` (a rule fails while running, the rule set as a whole), `"limit"` (`max_iterations` or `max_triples` exceeded, as the RDFC-1.0 cap), `"expression"` (a node expression cannot be evaluated), `"limit"` also covers shapes or node expressions past the depth limit (context says which; the kind `"nesting"` was merged into `"limit"` on 2026-11-26), `"recursion"` (a data cycle through `sh:not`), `"constraint-query"` (`?failure true`), `"internal"` (the engine failed an assertion about its own result, a bug in StarLayer to report: `derive_shape()`'s self-check); three more kinds belong to OWL-DL reasoning in `starlayer-reasoning` (`"timeout"`, `"inconsistent"`, `"inference"`: Java missing or broken, or a crashed reasoner child; a missing Python package is an `ImportError`) and propagate out of `validate()` / `apply_rules()` when `inference=ENTAILMENT["OWL-Direct"]` is used; the engine itself never raises them; **class and `kind` name the cause and never change with the path the error travels (decision 2026-11-25):** an expression that cannot be evaluated is `"expression"` from `validate()`, from a rule and from `extract_subgraph()` alike, and `"rule"` is only for a failure of the rule itself (a foreign exception out of a rule's query); `max_iterations` and `max_triples` are `"limit"`; where it happened (which rule, shape, focus node, call) is in the message and in `error.context`, an optional short string (default `None`) on `ExecutionError` and `ShapeError` (whatever its kind), set with `rules._prefixed` / `_renamed`, which keep the object, its class and its kind. A handler adds context and re-raises; it never relabels, and no path that is not told to continue swallows an `ExecutionError` or `ShapeError` (a rule's `sh:values`, fragment extraction). A missing module of our own package is `"internal"`. `RuleResult.failures` stays a list of messages. The per-kind classes (`RuleError`, `EvaluationFailure` ...) were removed on purpose, no aliases (2026-11-25). A new raise site picks the class by who is at fault (`ShapeError` kind `"compile"` for a ValueError found while compiling, `ExecutionError` while running, plain `ValueError` only for a bad argument of a public call) and the kind by what failed. **A clause that means "no value" (`except ExecutionError`) must call `only_kind(error, "expression")` (from `starlayer.errors`) first**, so a `"rule"`, `"limit"`, `"recursion"` or `"constraint-query"` error still propagates. **A custom function called from a SPARQL expression** (`sparql_support.shacl_functions`) gives no value (unbound, a SPARQL error) only for kind `"expression"`; any other kind and any `ShapeError` of the body is kept and raised by `run_query_with_functions` when the query has run, because pyoxigraph turns any exception raised in a custom function into an unbound value. Run every engine query that can call a function through `run_query_with_functions`, never `run_query` with `shacl_functions` directly. **A `StarShaclProcessor` raises them when it is built**, not at the first `validate()`: with a `shacl_graph` the constructor compiles the plan (`Plan.compile()`, kept and reused by `validate()`; the module-level `validate()` and `apply_rules()` compile per call). The parameters are checked through the `check=` hook of `@component(...)` (`ComponentSpec.check(shapes, shape, params)`: reads the parameters with the helpers the component's function uses, returns the shape nodes they refer to); a new component that reads a parameter registers one. Still evaluation-time: node expressions, SPARQL query text, the validators of SPARQL-based components, target expressions, and anything that needs the data. SPARQL in shapes declares prefixes only with `sh:declare` / `sh:prefixes`; there is no ambient lookup. The legacy SHACL-AF forms (a bare `sh:path` as an expression, untyped rules, `sh:filterShape`, SPARQL-based targets) are not supported: use `shnex:pathValues`, typed rules, `shnex:filterShape`. `sh:this` is accepted as an ordinary IRI (a constant, not the focus node) and the meta-shapes warn about it: write `[ shnex:var "focusNode" ]`.
- **`meta_shacl` is off by default.** Bound at construction (`StarShaclProcessor(meta_shacl=True)`) it runs once there, before the compile (`ShapeError` kind `"meta"` from the constructor), and `validate()` does not repeat it (`_adapter.CheckedShapes` keeps the result per shapes-graph fingerprint, so a call's `meta_shacl=True` on any processor is also run once per unchanged graph; `meta_shacl=False` on a call is allowed). **The check is strict and has no setting for it (decision 2026-11-25):** a Violation, Warning or Info result makes the shapes graph invalid (SHACL 1.2 Core's default set; the W3C SHACL-for-SHACL says a Warning shape is deactivated, not ignored; pySHACL's meta check is strict too). `meta_validate()` takes no `allow_warnings` / `allow_infos` (a `TypeError`, no alias), and a processor's own `allow_warnings` / `allow_infos` describe the data validation only: `_adapter._meta_preflight` passes none, so processor, `meta_validate()` and pySHACL agree (`tests/shacl/integration/test_meta_strict_severity.py`). An editor that wants a warning not to block reads the results from `ShapeError.report_graph` (kind `"meta"`). The engine function `engine.meta.meta_validate` keeps `allow_warnings` / `allow_infos` (default off) only so a test can read a warning's report without the raise; no public path sets them. The meta-shapes are built, not assembled at run time: edit `packages/starlayer/starlayer/starontology/_sources/shacl12-validation-shapes.ttl`, run `python scripts/build.py`, and the library reads the stored `starontology/shacl/shacl12-shacl.ttl`. A test fails if the stored file drifts from a fresh build. **The base is the W3C Working Group's own SHACL-for-SHACL, pinned in `packages/starlayer/starlayer/starontology/_sources/vendor/` and only ever added to** (never delete or edit its triples; relax a rule with `sh:deactivated true` and put the replacement in the asset). The shipped rules (`starontology/shacl/shacl12-shacl-rules.ttl`) are SHACL 1.2 rules and run on the engine. **Layering:** `shacl_shacl` is standard SHACL and standard SPARQL only, so any SHACL 1.2 processor can run it. The checks that need a StarLayer function (an invalid `sh:pattern` / `sh:flags`, the SPARQL text of `sh:select` / `sh:ask` / `sh:construct` / `shui:searchQuery`, the argument count of a node expression call) are `sh:sparql` shapes that ask StarLayer-internal SPARQL functions (`engine/builtin_functions.py`; not part of the public API); they are in the hand-edited, private layer `shacl_shacl_starlayer` (`starontology/shacl/shacl12-shacl-starlayer.ttl`; not in the `starontology` registry, loaded by `starontology._load_private`), which `load_meta_shapes_graph()` merges in. The query text check also asks the engine's own restrictions (`sparql_support.restriction_problem`: SERVICE, and, where `?this` is pre-bound, MINUS, VALUES and assignment of it, a SELECT that does not project it) once `meta_shapes.query_context` / the shape's `?context` says where the query is used, and `stsh:ArgumentCountShape` asks `expressions.ARITY` (`stsh:argumentCountProblem`): the engine and the meta check read the same code and table. **Meta shapes mirror the engine's compile errors as far as shapes can say them** (a literal shape reference, a `sh:NodeShape` with `sh:path`, `sh:reifierShape` without an IRI path, `shnex:limit`/`offset`, a prefix declared twice, two custom functions in one call; tests in `tests/shacl/integration/test_meta_shapes_extensions.py` pair each rule with the engine). What stays engine-only because the data, an option or evaluation decides it: recursion through `sh:not` on a data cycle, `Validation path too deep`, a cyclic or self-calling node expression, `?failure true`. Their results are ordinary ones (`sh:sourceShape` is `stsh:RegexShape` or `stsh:SPARQLQueryTextShape`, the component `sh:SPARQLConstraintComponent`), and `sh:deactivated true` in a `meta_shapes_extra` graph switches them off. **Scoped check (`engine/meta_scope.py`, internal):** `meta_validate(add=, remove=, full=)` and `meta_scope(add=, remove=, full=)` are the public surface (decision 2026-11-25: `nodes=` and `with_dependents=` are engine-only, a call with either is a TypeError, no alias; `meta_scope`, `MetaScope` and `ShapeError.scope` stay; the engine function `engine.meta.meta_validate` keeps both parameters and the tests call it); a risky edit (`FULL_CHECK_TRIGGERS`) is checked in full by itself, `full=True` forces it.
- **`owl:imports` follow the one import rule (decision 2026-11-26; the code is `graph/imports.py::resolve_or_raise`, `shacl/engine/imports.py` is the shapes-graph wrapper).** `validate()`, `validate_each()`, `apply_rules()` and a `StarShaclProcessor` resolve the imports of the shapes graph (the data graph when there is no shapes graph) and of `ont_graph` or raise `ExecutionError` kind `"import"` (`error.unresolved` the IRIs, `context` `owl:imports <iri>`; it was a compile error). An import is satisfied when its IRI is a subject of the graph after resolution (present, built in, or loaded), or the `owl:versionIRI` of a present ontology: no loader, a `imports_loader` that returns `None` or a graph without the IRI is the error (it was skipped), and a loader that raises is wrapped (the exception is `__cause__`). `ignore_imports=True` loads and checks nothing (also with a loader). Nothing is fetched on its own and nothing retried: an application reads `starlayer.graph.unresolved_imports(shapes)` and calls again. A processor checks at construction with its own loader / `ignore_imports`; with neither, unsatisfied imports skip the eager check (a call may bring a loader) and raise at `validate()`; a loader given at construction that cannot resolve them raises at construction. An `owl:imports` object that is not an IRI stays a `ShapeError` kind `"compile"` (the shapes graph is wrong). **Built in (decision 2026-11-25):** an import of any ontology IRI declared (`owl:Ontology`) by a graph registered in `starontology` (today `sh:`, SHACL UI, SHACL-SHACL, SKOS) is satisfied with no loader, is never passed to a loader and adds no triples (`builtin_import_keys()` in `graph/imports.py`, lazy, cached, no list kept), and one trailing `#` or `/` is ignored. **On the graph (2026-11-26):** the loader and flag are the graph's own (`StarLayerGraph(imports_loader=, ignore_imports=)`, `graph.resolved_imports()`, see `graph/CLAUDE.md`); `imports_loader=` / `ignore_imports=` on a call (or on the processor's constructor) override them (`ignore_imports=None` is the graph's own). `engine/imports.py::resolve_inputs(data, shapes, ont, ...)` is what every run calls: the shapes graph (the data graph when there is none) and `ont_graph` are extended with their imports; the data graph's own imports are resolved too (an unresolved one raises) but are given to entailment only, appended to `ont_graph` as a list of triples, never added to the data. It is called by `validate()`, `validate_each()` (shapes and ontology once, `imports_resolved=True`; each data graph its own), `apply_rules()`, `evaluate()`, `target_nodes()`, `target_shapes()`, `extract_subgraph()`; `close_shape()` and `select_widgets()` (shapes and scoring graph, `data_graph` checked) and `derive_shape()` (`template_graph`; `graph` checked) resolve the graphs they read; each of those, and the matching `StarShaclProcessor` methods, takes `imports_loader=` and `ignore_imports=`. A resolved graph that gained triples is a new graph, and the entailment cache keys the ontology by a fingerprint of its triples, so a changed loader or import set is another entailed copy. `starontology` registry graphs do not carry a loader: `sqe_shacl`, `srl_shacl` and `manchester_shacl` import shapes graphs that are not built in, so validating them as data or shapes needs `ignore_imports=True` or `imports_loader=starontology.local_loader`.
- **`shapes_graph_resource=`** selects a named `sh:ShapesGraph` module of the bound shapes graph (its IRI becomes `sh:usedShapesGraph`), or is only a provenance tag when the graph does not contain it. With no bound shapes graph it raises. **Provenance has one form (2026-11-23)**: a blank `sh:ValidationActivity` that `prov:generated` the report carries `sh:usedDataGraph`, `sh:usedShapesGraph`, `sh:usedConfiguration` and `prov:wasAssociatedWith` the `sh:ValidationAgent` (the StarLayer IRI of the conformance declaration); the report node has none of them (`engine/report.py::annotate_provenance`, read by `engine/text.py` and `profiling/profiles.py`). No timestamps.
- **A passing test is not proof.** Check that a fixture would fail on the behaviour you changed; for meta-shapes, check that a malformed value is rejected, not only that a valid one passes. The W3C suites run through `tests/shacl/w3c_shacl12/` (engine runners: `test_w3c_engine_*.py`; deviations from a fixture are asserted, not skipped).
- **The six SHACL 1.2 documents are all still moving.** Status and procedure: `docs/design/shacl/shacl12-gap-matrix.md`, "Tracking Upstream Spec Changes".

## Design history

The dated log of the pySHACL-backed validator (its monkeypatches, the triple-term adapter, `native_components`, and the fixes made to it, 2026-10-06 to 2026-10-30) is archived in `docs/working/archive/shacl-claude-md-pyshacl-era.md`; the code it describes was replaced by the engine (`docs/working/archive/shacl-engine-cutover.md`). Decisions that still hold and live in the code they describe:

- **Shape typing is a rule set** (`shape_types.infer_types()`, `starontology/shacl/shacl12-shacl-rules.ttl`): a shape need not carry `rdf:type` (Core 3.1 to 3.3).
- **Widget selection** (`ui/widget_selection.py`) follows SHACL UI 4.3: a widget a shape names is scored, and `shui:defaultWidgetScore` is read; `select_widgets(per="shape")` answers once per property shape.
- **`extract_subgraph()`** is the shape fragment of the Shape Fragments paper; the Conformance Theorem is its contract (`subgraph_extraction.py`, module docstring).
- **`derive_shape(graph, cls=... | node=..., shape=, template_graph=)`** (fresh: exactly one of `cls=`/`node=`; with `template_graph=`: `shape=` only) (`derive.py`) is a StarLayer feature, not SHACL: one node shape for a class (all instances, subclasses by default) or for one node, as a new graph (a fresh derivation is `sh:closed true` with the default `sh:ignoredProperties`; **with a template the template's `sh:closed` setting stays (2026-11-25)**: open stays open with no `sh:closed` added, `sh:closed false` stays, `sh:closed true` stays closed and gets the default ignored list merged in; a property the data has and the template lacks is added in every case), named `ex:PersonShape` / `ex:AliceShape` unless `shape=` says otherwise. **With a `template_graph`, `shape=` is required and names the template shape to update (2026-11-25; the old lookup by `cls=`/`node=` is gone, no alias)**: the target is read from that shape (exactly one `sh:targetClass` or one `sh:targetNode`; none, several, another kind of target or an implicit class target is a `ValueError`), `cls=`/`node=` together with `template_graph=` is a `ValueError`, a `shape=` that is not in the template is a `ValueError`, the result keeps the template shape's name (no rename in this call), and the other template shapes are not copied. **Loosen, else deactivate (2026-11-25):** a template constraint the data breaks is recomputed when it can be, else deactivated with a reifier on its own triple (`{| sh:deactivated true |}`; never dropped, and no longer left active for `sh:sparql` or custom components); a `sh:minCount` is lowered to the fewest values any node has; **a constraint is loosened only to a non-empty one, else deactivated with its original value kept (2026-11-25)**: `sh:minCount` when that is 0, `sh:datatype` ("the values share no single datatype"), `sh:class` ("the values share no class"), `sh:languageIn` ("a value has no language tag"), `sh:nodeKind` ("the values are of every node kind"); a loosened `sh:nodeKind` stays a `sh:nodeKind` (never turns into `sh:datatype`/`sh:class`), and the comment never says "to no constraint"; constraints the data satisfies are untouched; every change goes in one `rdfs:comment` on the node shape (none when nothing changed; comments on property shapes are gone). The declarations of used custom constraint components are copied into the result. It validates its result before returning, so it lives here and not in the graph package; the output has no randomness (blank node ids are computed).
- **`sh:targetWhere`** validates the where-shape only and may target literals; `sh:targetNode` takes a node expression (evaluated with the shape as focus node, Core 3.1.3.1).
- **`StarShaclProcessor` binds** a shapes graph (and optional ontology, data and scoring graph) at construction, not per call; the entailment regime is bound at construction as a default and a call's `inference=` replaces it for that call (2026-11-22; it was a `TypeError` before, `evaluate()` included). The options listed under "Options are a closed set" (severity, `meta_shacl`, imports, `subclass_of_in_shapes_graph` and the iteration limit) are different: bound at construction as defaults, and a call can override them. The shapes graph is checked and compiled at construction and again when `shacl_graph` is assigned (a bad one leaves the processor as it was); a graph edited in place is fingerprinted at each `validate()` and re-read if it changed, so the error then comes from `validate()`.
