# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo. See `docs/guides/README.md` for the docs index (start with `packages/starlayer/docs/shacl/implementation-plan.md`).

## Rules that bite

- **There is one engine.** `starlayer.shacl` is a thin public layer (`validator.py`, `_adapter.py`) over the native SHACL 1.2 engine in `starlayer/shacl_engine/`; nothing here imports pySHACL, and pySHACL is not a dependency. The engine follows the SHACL 1.2 drafts (Core, SPARQL Extensions, Node Expressions, Inference Rules), not SHACL-AF (2017) or pySHACL extensions: where an old test or habit disagrees, check the draft, and record a deliberate deviation in `docs/working/shacl-engine-differential.md`. Design: `docs/working/shacl-engine-design.md`.
- **Shape of the API.** Everything an application needs is importable from `starlayer.shacl` (see `__init__.py`): `validate`, `validate_each`, `apply_rules`, `evaluate`, `target_nodes`, `extract_subgraph`, `StarShaclSchema`, the result types, the errors (`ShapeError`, `RuleError`, `MetaShaclError`, `EvaluationFailure`), `evaluate_expression`, `node_expression_functions`, `infer_types`, `path_values`, `select_widgets` and the other helpers. **Apps do not import submodules.** If an app needs something only a submodule has, add a public component and say so in `docs/working/workbench-api-needs.md`; do not leave a shim at an old path.
- **A dataset is its union.** SHACL validates one data graph; `validate` (and `evaluate`, `apply_rules`) sees a `StarLayerDataset` as the union of all its graphs whatever its own `default_union` says, as pySHACL does (`terms._union_view`). `validate_each(dataset)` validates the graphs one by one (keys: graph names, `None` for a default graph that holds triples; a mapping keeps its keys, a sequence is keyed by position). `extract_subgraph` and `relevant_subgraph` refuse a dataset (`TypeError`): a fragment would not say which graph a triple came from; pass one graph or `dataset.to_graph()`.
- **Options are a closed set.** `validate()` and `apply_rules()` take the named parameters plus the options listed in `_adapter.VALIDATE_OPTIONS` (`inference`, `inplace`, `meta_shacl`, `advanced`, `allow_warnings`, `allow_infos`, `abort_on_first`, `max_validation_depth`, `invalid_terms`; `apply_rules` also `max_iterations`, `max_triples`). Anything else is a `TypeError`. `mode=` is an option preset (`validation_modes.py`), not a SHACL Profile: "Profile" means only the SHACL 1.2 Profiling spec (`shacl_profiling`).
- **Results.** `ValidationResult`; `RulesResult(inferred_graph, validation)`, where `inferred_graph` is only what the rules produced (plus `sh:sourceRule` reifiers on request) and the caller's data is never touched; `evaluate()` and `extract_subgraph()` return a plain graph. Result messages are processor-defined: the report graph carries the engine's default wording unless the shape (or the constraint's reifier) has a `sh:message`, and `report_text` shows nested `sh:detail` results.
  Default message conventions (`shacl_engine/text.py`, `generic_message`): built from the result's structured fields (component, path, value) and the shape's parameter value, never parsed back by callers (the report row keeps `sh:sourceConstraintComponent`, `sh:resultPath`, `sh:value`, `sh:sourceShape`; read those, not the text). One sentence, no final period, no `a->b` path notation: a value constraint reads `Value <value> should <expectation>` (`should be at least 5`, `should have the datatype xsd:integer`, `should be an IRI`, `should be one of 1, 2`); a count constraint reads `Needs at least <n> value(s) for <path>` / `Allows at most <n> value(s) for <path>`, with the singular only for exactly 1; a blank-node value is `A blank node value` (its label means nothing); terms are prefixed names, literals are quoted (bare for numbers). W3C conformance does not compare message text.
- **Entailment uses the graph package's IRIs** (`inference=ENTAILMENT.RDFS`, or `sh:entailment` in the shapes). The old string names (`"rdfs"`, `"owlrl"`) are rejected on purpose.
- **Terms that are not RDF terms** (a relative IRI) raise `TermError` unless `invalid_terms="lenient"`; the library's own query-tree and ontology validators pass `lenient`.
- **Ill-formed shapes raise `ShapeError`** (a `sh:NodeShape` with `sh:path`, a `sh:property` value without `sh:path`, a list expression member that is a node expression, a malformed regex ...), rule problems `RuleError`. SPARQL in shapes declares prefixes only with `sh:declare` / `sh:prefixes`; there is no ambient lookup. The legacy SHACL-AF forms (`sh:this`, a bare `sh:path` as an expression, untyped rules, `sh:filterShape`, SPARQL-based targets) are not supported: use `[ shnex:var "focusNode" ]`, `shnex:pathValues`, typed rules, `shnex:filterShape`.
- **`meta_shacl` is off by default.** The meta-shapes are built, not assembled at run time: edit `scripts/assets/shacl12-validation-shapes.ttl`, run `python scripts/build.py`, and the library reads the stored `starontology/shacl12-shacl.ttl`. A test fails if the stored file drifts from a fresh build. **The base is the W3C Working Group's own SHACL-for-SHACL, pinned in `scripts/assets/vendor/` and only ever added to** (never delete or edit its triples; relax a rule with `sh:deactivated true` and put the replacement in the asset). The shipped rules (`starontology/shacl12-shacl-rules.ttl`) are SHACL 1.2 rules and run on the engine.
- **`owl:imports` that are not already in the shapes graph raise** in `validate()` unless you pass a loader (`shapes_graph_loader=`) or `ignore_imports=True`. Nothing is fetched on its own.
- **`shapes_graph_resource=`** selects a named `sh:ShapesGraph` module of the bound shapes graph (its IRI becomes `sh:usedShapesGraph`), or is only a provenance tag when the graph does not contain it. With no bound shapes graph it raises.
- **A passing test is not proof.** Check that a fixture would fail on the behaviour you changed; for meta-shapes, check that a malformed value is rejected, not only that a valid one passes. The W3C suites run through `tests/shacl/w3c_shacl12/` (engine runners: `test_w3c_engine_*.py`; deviations from a fixture are asserted, not skipped).
- **The six SHACL 1.2 documents are all still moving.** Status and procedure: `packages/starlayer/docs/shacl/shacl12-gap-matrix.md`, "Tracking Upstream Spec Changes".

## Design history

The dated log of the pySHACL-backed validator (its monkeypatches, the triple-term adapter, `native_components`, and the fixes made to it, 2026-10-06 to 2026-10-30) is archived in `docs/working/archive/shacl-claude-md-pyshacl-era.md`; the code it describes was replaced by the engine (`docs/working/shacl-engine-cutover.md`). Decisions that still hold and live in the code they describe:

- **Shape typing is a rule set** (`shape_types.infer_types()`, `starontology/shacl12-shacl-rules.ttl`): a shape need not carry `rdf:type` (Core 3.1 to 3.3).
- **Widget selection** (`ui_widget_selection.py`) follows SHACL UI 4.3: a widget a shape names is scored, and `shui:defaultWidgetScore` is read; `select_widgets(per="shape")` answers once per property shape.
- **`extract_subgraph()`** is the shape fragment of the Shape Fragments paper; the Conformance Theorem is its contract (`subgraph_extraction.py`, module docstring).
- **`sh:targetWhere`** validates the where-shape only and may target literals; `sh:targetNode` takes a node expression (evaluated with the shape as focus node, Core 3.1.3.1).
- **`StarShaclSchema` binds** a shapes graph (and optional ontology, data, scoring graph and entailment regime) at construction, not per call; `validate(inference=...)` on a schema is a `TypeError`.
