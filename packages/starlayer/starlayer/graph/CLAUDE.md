# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo. See `docs/guides/README.md` for the docs index (start with the Oxigraph-backed graph guide, `docs/guides/02d-oxigraph-wrapper.ipynb`). The older notes in `docs/design/graph/` describe the deleted rdflib-based class.

## Rules that bite

- **One class, one backend.** `StarLayerGraph` (one graph) and `StarLayerDataset` (a store of named graphs) are composition wrappers over a `pyoxigraph.Store`, defined in `core.py` and re-exported by `starlayer.graph` and `starlayer`. Terms are pyoxigraph terms. The old rdflib-based classes, hand-written parsers and serializers, `tt:` encoding, rdflib stores and the rdflib evaluator patches were deleted at D1.
- **rdflib is optional and only in the conversion.** A function that takes a graph does not take an rdflib `Graph` (`engine_view` raises `TypeError` naming `from_rdflib`). `from_rdflib` / `to_rdflib` (out is the RDF 1.2 Interoperability basic encoding, as `serialize(rdf_version="1.1")`) are in `graph/rdflib_bridge.py` and `graph/rdflib_model/` (`TripleTerm`, `DirLangString`), which import rdflib inside functions; `core.py::_rdflib_bridge` reaches them only when a conversion runs and raises an `ImportError` saying `pip install "starlayer[rdflib]"`. `owlrl` and the OWL-DL engines are in the separate `starlayer-reasoning` package (`infer.py::_reasoning`, with `pip install starlayer-reasoning`). `tests/packaging/test_no_rdflib_import.py` keeps every other import of rdflib or a reasoner out of the core.
- **Oxigraph's store methods are on the classes; a writer keeps the write counter.** `load`, `bulk_load`, `bulk_extend`, `add_graph`, `clear_graph` (and `add`, `extend`, `remove`, `update`) call `union.touch()`, which the entailment cache and the deduplicated union copy depend on, so a new writing method must too. A method that names a graph acts on that graph alone on a `StarLayerGraph` (`_own_graph` raises `ValueError` for another); `flush`, `optimize`, `backup`, `named_graphs`, `contains_named_graph` are store-wide. Other names are not forwarded (`AttributeError`); `read_only` and a graph's `remove_graph` go through `.store`. A write on `.store` itself needs `union.touch()` (or `as_store()`, which does it).
- **Entailment regimes are the W3C IRIs**, `ENTAILMENT.RDFS`, `ENTAILMENT["OWL-Direct"]` and so on, for both `infer(entailment=...)` and `query(entailment=...)`. Not strings.
- **Literals are normalised by the Oxigraph store** (`04` becomes `4`, a decimal `4.0` becomes `4`); the datatype and meaning are kept, the spelling is not (starlayer #190, Oxigraph PR #2010). Accepted for now.
- **StarLayer needs Oxigraph >= 0.5.13** (pyoxigraph): older versions abort the whole process on SPARQL `=` between two `dirLangString` terms (oxigraph/oxigraph#1982). The installed pyoxigraph is checked at import (`_versions.py::require_supported_pyoxigraph`).
- **Do not import the SPARQL grammar lazily while pytest is collecting.** It corrupts the shared grammar (still used by the `sparql/` parsers) for the rest of the run. `tests/conftest.py` imports and installs it eagerly.
- **Some strings are infrastructure, not names.** Namespace IRIs in bundled data are data identity, so renaming one is a breaking change.
- **Test tiers.** The W3C suites are pinned to a commit (bump `PINNED_SHA` deliberately and read the diff). Integration tests need local servers and skip without them.
- **Check the spec before RDF/SPARQL 1.2 work:** from `packages/starlayer`, `python tests/graph/vendor/spec_snapshots/refresh_snapshots.py` and `git diff` the snapshots. To see what moved upstream (specs, the pinned W3C test suites, the vendored vocabularies): `python scripts/check_spec_drift.py`; after a review, `--record`. It runs only when you run it.
- **`rustdl` is young and has changed behaviour between versions** (a silent incomplete answer became a hang). Re-verify any claim about it against the installed version.

## How the code is laid out

- **Classes** (`core.py`): `_Base` holds what the two share. `StarLayerGraph` is one graph of a store (the default graph, or the named graph `identifier`); `StarLayerDataset` is the whole store, with `default_union` to read all graphs as one. `path=` opens an on-disk RocksDB store; `store=` wraps an existing `pyoxigraph.Store` (`as_store()` hands it back; call `oxgraph.union.touch()` after writing to it directly).
- **Terms** are pyoxigraph `NamedNode`, `BlankNode`, `Literal` and `Triple` (a triple term is a `pyoxigraph.Triple`). `terms.py::term` takes pyoxigraph terms, 3-tuples (triple terms); **an rdflib term is a `TypeError`** (convert a whole rdflib graph with `from_rdflib`). `starlayer.graph` ships `Namespace` and `RDF`, `RDFS`, `XSD`, `OWL` (and `starlayer.shacl.SH`) as `NamedNode` constants. Reifiers and triple terms are read and written through `reification.py`.
- **Parse and serialize** are Oxigraph's. The wrapper adds the `@version` / `VERSION` declaration (`ntversion.py` validates it in N-Triples and N-Quads, which Oxigraph rejects), the `rdf_version="1.1"` export in the Interoperability basic encoding (`interop.py`), pretty Turtle (`pretty.py`) and Manchester syntax (`parsers/manchester_parser.py`, `serializers/manchester.py`). There are no other parsers or writers.
- **`query()` / `update()`** send the text to `Store.query` / `Store.update` unchanged (`execution/run.py`): `custom_functions` / `custom_aggregate_functions` (Python functions callable from the query, Oxigraph's own) go straight through, also for `update()` and an entailment session; `Result.serialize()` writes SPARQL Results JSON, XML, CSV and TSV (Oxigraph's writers over the rows) or RDF for CONSTRUCT and DESCRIBE; `initNs` becomes `prefixes=`, `initBindings` becomes `substitutions` (a `VALUES` clause when the variable is not projected), a `VERSION` directive is checked (`execution/sparql_text.py`). Nothing is lowered or rewritten, except for an update on a `default_union` dataset (last sentence below) and for `entailment=`: RDF and RDFS rewrite the query (`sparql/sqe/entailment.py`); the OWL regimes run the query on a throwaway copy of the store plus the entailed triples, which the graph keeps per regime and engine (`_entailed`, `core.py::_entailed_triples`) and recomputes by `infer=` (`"changed"` compares the `union.current()` write number; a write on a raw store reference needs `union.touch()`). `entailment_session()` (`execution/session.py`, `EntailmentSession`) keeps that copy for repeated queries until `close()`; a plain `query(entailment=...)` copies the store on every call. A `default_union` dataset that holds a triple in several graphs queries a deduplicated copy of the store (`execution/union.py`), because Oxigraph counts such a triple once per graph. An update on a `default_union` dataset reads a copy of the union kept in a scratch graph (`run.update`).
- **`infer()`** (`graph/entailment/infer.py`): RDF and RDFS natively (`graph/entailment/rdfs_closure.py`, equal to owlrl's `RDFS_Semantics` as configured here, tested against it); OWL-RL and combined regimes (`owlrl` on an rdflib copy) and OWL-Direct (HermiT or `rustdl`, with a subprocess timeout) through `starlayer-reasoning` (`owl_rl_delta`, `owl_direct_delta`). The regime IRIs are `graph/entailment.py::ENTAILMENT`.
- **Other helpers:** `rewrite.py` (`skolemize`, `de_skolemize`, `cbd`, `empty_like`), `imports.py` (`owl_imports`, `resolve_imports`), `shapes.py` (`derive_shape`), `qnames.py` (`qname`, `expand_curie`), `setops.py` (`union`, `intersection`, `difference`), `rdfc_native.py` (Oxigraph's RDFC-1.0 canonical forms and hash, with a guard that raises `CanonicalizationComplexityError` on a symmetric blank-node structure), `compare.py` (`isomorphic`) and `rdfc.py` (`rdfc10_hash`, `to_canonical_nquads`, thin fronts over `rdfc_native`).
- **Not in the core:** `owlrl` and the OWL-DL engines (in `starlayer-reasoning`; its tests are in `packages/starlayer-reasoning/tests`). Manchester syntax is native.
- **Remote endpoints:** `StarLayerGraph(endpoint=Endpoint(query_url, update_url), identifier=...)` holds one graph, and `StarLayerDataset(endpoint=...)` all the graphs, of a SPARQL endpoint (Oxigraph server, Fuseki; tested against both). `BackedStore` (`endpoint.py`) stands in for the `pyoxigraph.Store`: a full local copy, pulled as a stream when the object is made, in memory or on disk with `path=` (an in-memory store is about 500 to 650 bytes a triple, on disk about 70 and a fixed small amount of memory), `pull=False` to open an existing copy. Reads are local. Every write goes to the endpoint first, then the copy, so the copy cannot get ahead of the endpoint; `update()` text runs on the endpoint only and the copy is pulled again; `sync()` / `max_age=` see other writers. Blank nodes in a write are skolemized (the endpoint would rename them); one that came from the endpoint cannot be written. There is no lazy or per-call copy: a graph too big for disk would need the work done on the server. A query can also read an endpoint with `SERVICE` (guide 06b).
- **Tests:** `tests/graph/unit/` (the classes), `unit/`, `integration/` (servers; skipped without) and the pinned W3C suites `w3c_rdf12/`, `w3c_sparql12/`, `w3c_turtle12/`. Past decisions are in git history (`git log -- packages/starlayer/starlayer/graph`) and `docs/working/`.
- **Upstream workarounds** (Oxigraph, rdflib): `python scripts/kg.py run upstream-workarounds`; write-ups in `docs/upstream-issues/`.
