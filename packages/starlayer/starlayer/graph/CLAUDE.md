# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo. See `docs/guides/README.md` for the docs index (start with the Oxigraph-backed graph guide, `docs/guides/02d-oxigraph-wrapper.ipynb`). The older notes in `packages/starlayer/docs/graph/` describe the deleted rdflib-based class.

## Rules that bite

- **One class, one backend.** `StarLayerGraph` (one graph) and `StarLayerDataset` (a store of named graphs) are composition wrappers over a `pyoxigraph.Store`, defined in `oxgraph/core.py` and re-exported by `starlayer.graph` and `starlayer`. Terms are pyoxigraph terms. The old rdflib-based classes, hand-written parsers and serializers, `tt:` encoding, rdflib stores and the rdflib evaluator patches were deleted at D1.
- **rdflib is an optional extra.** `from_rdflib` / `to_rdflib` convert (out is the RDF 1.2 Interoperability basic encoding, as `serialize(rdf_version="1.1")`); `owlrl` runs on an rdflib copy. All of it goes through `oxgraph/_rdflib_bridge.py`.
- **Entailment regimes are the W3C IRIs**, `ENTAILMENT.RDFS`, `ENTAILMENT["OWL-Direct"]` and so on, for both `infer(entailment=...)` and `query(entailment=...)`. Not strings.
- **Literals are normalised by the Oxigraph store** (`04` becomes `4`, a decimal `4.0` becomes `4`); the datatype and meaning are kept, the spelling is not (starlayer #190, Oxigraph PR #2010). Accepted for now.
- **StarLayer needs Oxigraph >= 0.5.13** (pyoxigraph): older versions abort the whole process on SPARQL `=` between two `dirLangString` terms (oxigraph/oxigraph#1982). The installed pyoxigraph is checked at import (`backends/_versions.py::require_supported_pyoxigraph`).
- **Do not import the SPARQL grammar lazily while pytest is collecting.** It corrupts the shared grammar (still used by the `sparql/` parsers) for the rest of the run. `tests/conftest.py` imports and installs it eagerly.
- **Some strings are infrastructure, not names.** Namespace IRIs in bundled data are data identity, so renaming one is a breaking change.
- **Test tiers.** The W3C suites are pinned to a commit (bump `PINNED_SHA` deliberately and read the diff). Integration tests need local servers and skip without them.
- **Check the spec before RDF/SPARQL 1.2 work:** from `packages/starlayer`, `python tests/graph/vendor/spec_snapshots/refresh_snapshots.py` and `git diff` the snapshots. To see what moved upstream (specs, the pinned W3C test suites, the vendored vocabularies): `python scripts/spec_drift.py`; after a review, `--record`. It runs only when you run it.
- **`rustdl` is young and has changed behaviour between versions** (a silent incomplete answer became a hang). Re-verify any claim about it against the installed version.

## How the code is laid out

- **Classes** (`oxgraph/core.py`): `_Base` holds what the two share. `StarLayerGraph` is one graph of a store (the default graph, or the named graph `identifier`); `StarLayerDataset` is the whole store, with `default_union` to read all graphs as one. `path=` opens an on-disk RocksDB store; `store=` wraps an existing `pyoxigraph.Store` (`as_store()` hands it back; call `oxgraph.union.touch()` after writing to it directly).
- **Terms** are pyoxigraph `NamedNode`, `BlankNode`, `Literal` and `Triple` (a triple term is a `pyoxigraph.Triple`). `oxgraph/terms.py::term` converts rdflib terms and the `TripleTerm` / `DirLangString` value classes of `model/` on the way in. Reifiers and triple terms are read and written through `oxgraph/reification.py`.
- **Parse and serialize** are Oxigraph's. The wrapper adds the `@version` / `VERSION` declaration (`oxgraph/ntversion.py` validates it in N-Triples and N-Quads, which Oxigraph rejects), the `rdf_version="1.1"` export in the Interoperability basic encoding (`interop.py`), pretty Turtle (`oxgraph/pretty.py`) and Manchester syntax (`parsers/manchester_parser.py`, `serializers/manchester.py`). There are no other parsers or writers.
- **`query()` / `update()`** send the text to `Store.query` / `Store.update` unchanged (`oxgraph/run.py`): `initNs` becomes `prefixes=`, `initBindings` becomes `substitutions` (a `VALUES` clause when the variable is not projected), a `VERSION` directive is checked (`oxgraph/sparql_text.py`). Nothing is lowered or rewritten, except for an update on a `default_union` dataset (last sentence below) and for `entailment=`: RDF and RDFS rewrite the query (`sparql/sqe/entailment.py`); the OWL regimes run the query on a throwaway copy of the store plus the entailed triples, which the graph keeps per regime and engine (`_entailed`, `core.py::_entailed_triples`) and recomputes by `infer=` (`"changed"` compares the `union.current()` write number; a write on a raw store reference needs `union.touch()`). `entailment_session()` (`oxgraph/session.py`, `EntailmentSession`) keeps that copy for repeated queries until `close()`; a plain `query(entailment=...)` copies the store on every call. A `default_union` dataset that holds a triple in several graphs queries a deduplicated copy of the store (`oxgraph/union.py`), because Oxigraph counts such a triple once per graph. An update on a `default_union` dataset reads a copy of the union kept in a scratch graph (`run.update`).
- **`infer()`** (`oxgraph/helpers/entailment.py`): RDF natively; RDFS and OWL-RL through `owlrl` on an rdflib copy (`oxgraph/_rdflib_bridge.py`); OWL-Direct through HermiT or `rustdl` (`graph/graph/owl_dl*.py`, subprocess timeout in `_timeout.py`). The regime IRIs are `graph/graph/entailment_regimes.py::ENTAILMENT`.
- **Other helpers:** `oxgraph/helpers/rewrite.py` (`skolemize`, `de_skolemize`, `cbd`, `empty_like`), `helpers/imports.py` (`owl_imports`, `resolve_imports`), `helpers/shapes.py` (`derive_shape`), `helpers/qnames.py` (`qname`, `expand_curie`), `setops.py` (`union`, `intersection`, `difference`), `rdfc_native.py` (Oxigraph's RDFC-1.0 canonical forms and hash, with a guard that raises `CanonicalizationComplexityError` on a symmetric blank-node structure), `compare.py` (`isomorphic`) and `rdfc.py` (`rdfc10_hash`, `to_canonical_nquads`, thin fronts over `rdfc_native`).
- **Still rdflib** (optional extra): the `from_rdflib` / `to_rdflib` bridge (also what `isomorphic` and `rdfc10_hash` use for an rdflib input), `owlrl` and the OWL-DL exporters (`graph/graph/owl_dl*.py`), and Manchester syntax.
- **Remote stores:** none. A graph object does not speak to a SPARQL endpoint; a query can read one with `SERVICE` (guide 06b).
- **Tests:** `tests/graph/oxgraph/` (the classes), `unit/`, `integration/` (servers; skipped without) and the pinned W3C suites `w3c_rdf12/`, `w3c_sparql12/`, `w3c_turtle12/`. Past decisions are in git history (`git log -- packages/starlayer/starlayer/graph`) and `docs/working/`.
- **Upstream workarounds** (Oxigraph, rdflib): `python scripts/kg.py run upstream-workarounds`; write-ups in `docs/upstream-issues/`.
