# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo.

## Rules that bite

- **`sqe:` is the public "SPARQL query as RDF" vocabulary** (a flat, editable tree from the raw parse tree). `salg:` is the internal full-algebra encoding; do not expose it in public docs or output.
- **Import order matters.** `sparql/__init__.py` imports `parse12` first; it extends rdflib's shared grammar in place (`_grammar12.install()`), and `from_rdf.py` snapshots that grammar at import. Importing the package another way silently breaks later query evaluation.
- **Execution is Oxigraph's.** `StarLayerGraph.query()` / `update()` hand SPARQL 1.2 text to Oxigraph. `lower_rdf11` (the 1.2 -> 1.1 lowering for rdflib's evaluator) was deleted at D1 together with the rdflib evaluator patches; the passages below that describe it are history. `parse12` and the algebra tree stay for the `sqe:` / SRL encoders.
- **A bare Python `str` in the algebra is not a `Literal`** (`Literal("=") == "="` is `False`). `RelationalExpression.op`, `UNDEF` and similar are bare strings; the encoder converts them.
- **`translateAlgebra` ignores `query.prologue`**, and rdflib's version of it fails on some queries (see `docs/upstream-issues/rdflib-upstream-issues.md`, item 2). The project's own `serialize12.py` carries fixes.
- **`_vars` and `lazy` must be recomputed after decoding a Query's algebra, but not an Update's.**
- **A triple term can never be the subject or predicate of another triple term**, enforced at construction (`InvalidTripleTermError`), not just in the grammar.
- **Use bracket access for namespace terms that collide with methods:** `SALG["term"]`, not `SALG.term`.
- **A "conforms" test is not an execution test.** A query that only passes `query_to_rdf` plus SHACL validation has not been shown to decode and run. Every new query shape needs a test that runs it through the real path and compares the result with plain rdflib.
- **SRL (SPARQL Rules).** `parse_ruleset()` validates against the `srl:` shapes by default (about 140 ms; `validate=False` skips). `evaldata` is the spec's polarity: `WHERE DATA` and `NOT DATA` match the base graph. `IMPORTS` need a caller-supplied loader and nothing is fetched on its own. `RuleSet.plan()` shows the rule order. Aggregation and SRL-to-SPARQL are waiting on the spec.
- **The sqe path is pyoxigraph and needs no rdflib.** `parse_sparql.py` (the owned recursive-descent parser) builds pyoxigraph terms; `sqe_parse_to_tree` writes a `StarLayerGraph`; `sqe_tree_to_text`, `sqe_validate`, `rewrite_exists_text` and the RDF / RDFS entailment rewrite read it with pyoxigraph terms. A relative IRI, bad blank node label or bad language tag in a query is kept as the SHACL engine's reversible stand-in (`_oxterms.py`). The rewrites render through `sqe/_memtree.py` (no store, so lexical forms survive; a store rewrites `"007"^^xsd:integer`). The rdflib forms for salg, SRL and `sqe_tree_to_query` live in `_vocab_rdflib.py`, `sqe/_vocab_rdflib.py` and `_sqe_rdflib.py`; delete them with those users (`docs/working/e1-notes.md`).
- **sqe holds no `salg:` terms.** salg may use sqe's vocabulary, never the reverse. The shared encoder/decoder (`to_rdf.py`/`from_rdf.py`) has two per-call hooks (`_NS_OVERRIDES`, `_ENCODE_HOOK`/`_DECODE_HOOK`) that sqe sets to give triple terms, aggregates and `EXISTS` sqe/`spexpr:` terms; a new construct that leaks a `salg:` term fails `test_no_salg_terms_in_any_tree`.
- **The sqe coverage tests are an opt-in set**, left out of a normal run: `pytest tests/sparql/sqe_coverage --sqe-coverage` (about 4 minutes). It runs every W3C SPARQL 1.2 query fixture and 90+ per-feature queries through sqe, comparing with the same query on a `StarLayerGraph`/`StarLayerDataset`. The fixtures sqe cannot round-trip are in `packages/starlayer/tests/sparql/sqe_coverage/sqe_known_gaps.txt` as strict xfails; after a change, refresh it with `python -m tests.sparql.sqe_coverage.test_w3c_through_sqe --regenerate`. Add a feature query to `FEATURES` in `packages/starlayer/tests/sparql/sqe_coverage/test_sqe_features.py` when you add a construct. The same directory holds a Hypothesis suite (random valid queries must parse, render stably and return the same rows), differential suites against plain rdflib and against Oxigraph (the SPARQL 1.2 referee, via `pyoxigraph`), and a shape audit (corrupt each property of rich trees and require the shapes to notice); see the test file names there. Give a new sqe property its own shape and do not declare an `rdfs:domain` on a property several node types share.
- **Run the tests with** `cd packages/starlayer && pytest tests/sparql`. The W3C SPARQL 1.2 suite is pinned; seven subject-position fixtures are marked `xfail(strict=True)` because the suite itself is wrong (`docs/sparql/w3c-sparql12-test-suite-issues.md`).

## What is here

- **Purpose.** Represent a SPARQL 1.2 query or rule set as RDF so it can be stored, edited, validated and queried like other RDF data, and parse SPARQL 1.2 text for the pieces that need an algebra. Execution of SPARQL text is not done here: `StarLayerGraph.query()` / `update()` send the text to Oxigraph (see `graph/CLAUDE.md`).
- **Dependency direction.** `sqe:` and `srl:` hold no `salg:` terms; `salg/` imports the shared `spexpr:` pieces (`spexpr_codec.py`, `expr_families.py`, `expr_validation.py`), never the reverse. `sparql/` reaches into `graph/` (`StarLayerGraph`, `ENTAILMENT`, `oxgraph/_rdflib_bridge.py`) with imports inside functions, and `graph/` imports `sparql/sqe/entailment.py` for the RDF and RDFS regimes.
- **Parsing** (`parse12.py`, `_grammar12.py`, `_syntax_checks.py`): `_grammar12.install()` splices the SPARQL 1.2 productions (`<<( )>>`, `TRIPLE()`, annotations and reifiers) into rdflib's parser grammar in place; `prepare_query_12` / `prepare_update_12` give a post-`translateQuery` algebra tree in which a triple term is a `TripleTermNode` (`triple_term.py`, which rejects a triple term as the subject or predicate of another). `_syntax_checks.py` enforces grammar rules rdflib's parser does not. `check.py::check_query` says whether a text is valid SPARQL 1.2 and what is wrong if not. `parse_sparql.py` is the raw-parse-tree parser behind the `sqe:` encoder.
- **`sqe:`** (`sqe/`): the public "query as RDF" tree, flat and editable, with SHACL shapes for field-level UI validation. `sqe_parse_to_tree` / `sqe_tree_to_text` / `sqe_tree_to_query` / `sqe_validate` (and `sqe/entailment.py`, the RDF and RDFS query rewrite behind `query(entailment=...)`). Reached as `from starlayer.sparql import sqe`. Design notes: `sqe/vocab.py`.
- **`salg:`** (`to_rdf.py`, `from_rdf.py`, `vocab.py`, `salg/`): the internal full-algebra encoding with its own shapes and `find_unbound_projected_variables`. A generic recursive encoder over rdflib's algebra nodes (`query_to_rdf`, `rdf_to_query`, `update_to_rdf`, `rdf_to_update`, `queries_to_collection`); `from_rdf.py` discovers rdflib's expression table from the live grammar at import, which is why the import order above matters. Not shown in public docs.
- **SRL** (`srl.py`, `_srl_ast.py`, `parse_srl.py`, `srl_eval.py`, `srl_semantic_checks.py`): SPARQL Rules (Datalog-style) parsed to an AST (`RuleSet`), converted to and from RDF (`srl:` tree, validated by the `srl:` shapes in `starontology/`), checked for well-formedness, stratified and evaluated. Entry points: `srl.parse_ruleset`, `RuleSet.infer`, `RuleSet.query`, `RuleSet.plan`. Evaluation matches rule bodies with SPARQL on a `StarLayerGraph`, with the spec's pseudocode for dependencies, stratification and `WHERE DATA`. `IMPORTS` need a caller-supplied loader. Only `RuleSet` and `TriplePattern` of the AST are public.
- **`StarQuery`** (`star_query.py`): a prepared query plus the per-call options of `StarLayerGraph.query()`, to run on several graphs.
- **Text out** (`serialize12.py`): SPARQL 1.2 text from an algebra tree, on rdflib's `_AlgebraTranslator`, with the two shims in `_translate_patches.py` (applied on import of `serialize12`). `SELECT` and `CONSTRUCT` only; no `ASK` or `DESCRIBE`. Kept for the W3C regeneration tests; goes with the rdflib dependency (B3 / D4). `sqe/to_text.py` is the renderer that keeps the original prologue.
- **Still rdflib** (D4 backlog): the parser grammar, the algebra node classes, `serialize12`, `_translate_patches` and the `salg:` / `sqe:` decoders.

## Tests

- `tests/sparql/`: `unit/` (one file per area), `sqe_coverage/` (opt-in, see the rule above), `srl_conformance/`, `parse_sparql_conformance/`, `integration/` (servers; skipped without), `hunt/` and the pinned W3C suites `w3c_sparql11/` and `w3c_sparql12/` (the SPARQL 1.2 evaluation tests run on a `StarLayerGraph` / `StarLayerDataset`; the seven subject-position syntax fixtures are strict xfails).
- Every new query shape added to a "conforms" list (`query_to_rdf` plus shape validation) needs a companion test that decodes and runs it and compares the result with an independent engine (Oxigraph, or rdflib where it has an oracle). A conforms-only list once let two decode bugs through (`EXISTS` with a multi-triple block, `SUBSTR` binding).
- Past decisions are in git history (`git log -- packages/starlayer/starlayer/sparql`) and `docs/working/`.
