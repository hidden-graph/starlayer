# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo.

## Rules that bite

- **`sqe:` is the public "SPARQL query as RDF" vocabulary** (a flat, editable tree from the parser's syntax tree). The internal `salg:` algebra encoding, its shapes and the rdflib algebra machinery behind it were retired at E4; do not reintroduce `salg:` terms.
- **No rdflib in this package.** Everything here runs on pyoxigraph terms: the owned parser (`parse_sparql.py`), `sqe:` trees (`StarLayerGraph`s), SRL (`srl.py`, `_srl_ast.py`, `parse_srl.py`, `srl_eval.py`, `srl_semantic_checks.py`) and `StarQuery`. An rdflib graph given to SRL (`RuleSet.infer` / `.query`, `ruleset_to_tree(graph=...)`, `tree_to_ruleset`) or `StarQuery.run` is a `TypeError` naming `StarLayerGraph.from_rdflib`. `tests/packaging/test_core_without_rdflib.py` runs SRL with rdflib blocked.
- **Execution is Oxigraph's.** `StarLayerGraph.query()` / `update()` hand SPARQL 1.2 text to Oxigraph. SRL evaluates a rule body as one SPARQL `SELECT` per run of triple patterns, and a filter or `SET` expression as text with the solution's variables substituted, on `StarLayerGraph`s.
- **Triple terms in rules are `TripleTermNode`** (`triple_term.py`), a comparable, hashable parser `Node` of kind `TripleTerm`; an expression is the parser's own `Node` tree (`ExprNode`, structural equality) or a bare term. Never a pyoxigraph `Triple` in a pattern, which could not hold a variable. A triple term can never be the subject or predicate of another triple term or of a triple (`InvalidTripleTermError`; for rule sets the `triple_term_in_subject` / `triple_term_in_predicate` well-formedness issues).
- **The `sqe:` / `spexpr:` vocabulary names things as the SPARQL grammar does (2026-11-25, `docs/working/sqe-vocabulary-table-2026-11-25.md`):** a built-in or aggregate is a class named as typed (`spexpr:STR`, `spexpr:isIRI`, `spexpr:COUNT`, `spexpr:GROUP_CONCAT`; no `Builtin_` / `Aggregate_` prefix), and the parser's `Node.kind` is the same string. An aggregate holds its operand in `spexpr:expr` (`"*"` for `COUNT(*)`) and `spexpr:distinct` is the boolean true or absent; a call by IRI is `spexpr:FunctionCall` with `spexpr:iri`, `spexpr:args` and the same boolean `distinct`; `CONCAT` / `COALESCE` use `spexpr:args`. `EXISTS` and `NOT EXISTS` are two classes (`sqe:Exists`, `sqe:NotExists`, no `negated` flag; the parser nodes `Exists` / `NotExists` hold their group in `where`). The paths are `spexpr:PathSequence`, `PathAlternative`, `PathInverse`, `PathElt` and `PathNegatedPropertySet`. The prologue is `sqe:PrefixDecl` linked by `sqe:prefixDecl`. Removed with no alias: `Builtin_*`, `Aggregate_*`, `Function`, `FunctionExpression`, `ExistsExpression`, `TrueFilter`, `spexpr:graph`, `spexpr:vars`, `sqe:negated`, `PrefixBinding`, `prologuePrefix`; `tests/sparql/unit/test_sqe_vocabulary.py` fails if one comes back. `sqe:undef` is declared in the ontology.
- **The ordered children of `sqe:` and `spexpr:` are ordinals too (2026-11-25):** `sqe:where`, `alternatives`, `projection`, `template`, `describe`, `dataset`, `groupBy`, `having`, `orderBy`, `vars`, `rows`, `cells`, `operations`, `quads`, `triples`, `delete`, `insert`, `using` and `spexpr:args` (also the values of `IN` / `NOT IN`), `other` (the operands of an `&&`, `||`, additive or multiplicative chain) and `op` (the operators of an additive or multiplicative chain) are `ORDERED_PROPERTIES` of `sqe/vocab.py`. A blank node child carries `tree:ord`, a variable, IRI or literal sits in a `tree:Item`, a named node that two queries share (guide appendix B1) is held through an Item; a UNION alternative is a `sqe:GroupGraphPattern` node (its elements in `sqe:where`) and a VALUES row a `sqe:Row` (its terms in `sqe:cells`, UNDEF is the IRI `sqe:undef`). Text that is only a prologue (a lone `PREFIX` / `BASE` / `VERSION`, comments, or nothing: W3C syntax-update-38 to 40) is an update with no operation, so `sqe_parse_to_tree` loads it as an empty `sqe:UpdateRequest` and `sqe_tree_to_text` writes its prologue back (an empty string for comments or no text); any other text outside both grammars is `FormatError` kind `"sparql"` (2026-11-25). An empty sequence is no triple, so `WHERE { }`, `DESCRIBE <x>` without a `WHERE`, and `DELETE { }`/`INSERT { }` templates are the same tree as their absent forms (a Modify with both templates empty is written with an empty `DELETE { }`; `DESCRIBE` writes no `WHERE` for an empty group). A comparison (`=`, `<`, ...) holds one `op` and one `other`, not sequences, and `other` of a relational expression is always one operand: `IN` / `NOT IN` have no `other` but the ordered `spexpr:args` (none for `IN ()`), and any other operator with `args` fails the shape (2026-11-25). The renderers read through `graph/ordinals.py` and raise `FormatError` kind `"rdf"` for a tie, a missing or bad ordinal; `sqe_validate` reports the same as shape results. `sqe_validate` of a 4,000-triple query takes 0.6 s (it was 5.0 s on lists), and the tree can be hashed with RDFC-1.0 (it was refused on lists). `tests/sparql/unit/test_sqe_ordinals.py` is the test; `docs/working/` has the encoding decision notes.
- **A bare Python `str` in an encoded tree is `Literal(text, datatype=spexpr:PlainString)`; a variable is `Literal(name, datatype=spexpr:Variable)`.** The encoder (`parse_sparql._Encoder`) does both; `srl.py` reuses it for the leaves of the `srl:` tree.
- **An `srl:` tree is read back by rendering each expression node to text and parsing the text** (`srl._decode_expr`), so the decoded rule set equals the one written, up to the literal forms the Oxigraph store keeps (`"9.0"^^xsd:decimal` comes back `"9"`).
- **The RDFS closure behind `sqe_validate` and `srl_validate` is native** (`expr_validation.rdfs_schema` / `rdfs_entailed_copy`); `infer(ENTAILMENT.RDFS)` is native too (`graph/entailment/rdfs_closure.py`); only OWL-RL needs owlrl and so rdflib.
- **The ordered children of an `srl:` node are ordinals, not `rdf:List` (2026-11-25):** `tree:ord` on each child blank node, a `tree:Item` (`tree:ord`, `tree:value`) for an IRI or a variable, an empty sequence is no triple; the helpers are `graph/ordinals.py`, the shapes (once, for every vocabulary) are `starontology/tree/tree_shapes.ttl`, and a tie or bad ordinal makes `tree_to_ruleset` raise `FormatError` kind `"rdf"`. The argument and operand lists inside an expression are ordinals too: the `spexpr:` encoder is shared with `sqe:`. The 14 §4.2 constraints in `packages/starlayer/starlayer/starontology/srl/srl_shapes.ttl` read the sequences through `tree:ord` (an earlier sibling is a smaller ordinal under the same parent and property); `srl_validate` takes about 47 ms for 3 rules and 1.4 s for 40 (it was 2.3 s on lists).
- **SRL (SPARQL Rules).** `parse_ruleset()` does not validate (2026-11-25: any text the grammar accepts gives a rule set, as `sqe_parse_to_tree` does for a query): `srl_validate` reports the `srl:` shapes, the §4.2 conditions and an unorderable rule set, and running a rule set that breaks §4.2 raises `FormatError` kind `"srl"`. **The §4.2 conditions are written twice, on purpose (2026-11-25):** as SPARQL constraints in `packages/starlayer/starlayer/starontology/srl/srl_shapes.ttl` (`srl:UnboundHeadVariableShape`, `srl:VariableInUseShape` and twelve more, one per condition; each result's focus node is the offending element, which is what `srl_validate` reports) and as Python in `srl_semantic_checks.py` (what a run calls). The shapes are too slow for a run (about 17 ms for a three-rule set and 0.5 s for forty, against under a millisecond); `tests/sparql/unit/test_srl_wellformedness_agreement.py` fails if the two differ (the conformance suite's §4.2 negatives, the unit cases and seeded random rule sets), so change both together. Stratification (a cross-rule graph search) and decoding stay Python. An `IMPORTS` entry that is not resolved is an `sh:Warning` result of `srl:UnresolvedImportsShape` (one per IRI, focus node the `srl:RuleSet`), and does not make `conforms` false: the ordering check covers only the rules in the document. A SPARQL constraint runs once per focus node (about 0.1 to 5 ms each), so a shape that targets a common class (`srl:TriplePattern`) is paid per element. `evalground` (the spec's flag since 2026-11-19, renamed from `evaldata` in the Python field and the `srl:ruleEvalground` / `srl:negationEvalground` properties on 2026-11-25, with no alias: SRL trees stored with the old names no longer decode) has the spec's polarity: `WHERE GROUND` and `NOT GROUND` match the base graph, and the old `WHERE DATA` / `NOT DATA` is a parse error that names `GROUND` (a `DATA { }` block is unchanged). Well-formedness follows the spec's `inScope` / `inUse` (`srl_semantic_checks._check_sequence`): a variable name used inside a `NOT` or group pattern may not be set or used in a triple pattern elsewhere in the rule. `IMPORTS` need a caller-supplied loader and nothing is fetched on its own. A function called by IRI is a `FormatError` (kind `"srl"`) at parse unless it is one of SPARQL's seven XSD casts (`parse_srl._CASTS`; the draft lists no other and no way to supply one, and a function could read the graph or differ between calls, outside what stratification sees). Oxigraph's other casts (`xsd:date`, ...) are rejected too. `RuleSet.plan()` shows the rule order. Aggregation and SRL-to-SPARQL are waiting on the spec. The SRL conformance suite (`tests/sparql/srl_conformance`, 929 tests, about 10 minutes) is opt-in: `--srl-conformance`.
- **The sqe path is pyoxigraph and needs no rdflib.** `parse_sparql.py` builds pyoxigraph terms; `sqe_parse_to_tree` writes a `StarLayerGraph`; `sqe_tree_to_text`, `sqe_validate`, `rewrite_exists_text` and the RDF / RDFS entailment rewrite read it with pyoxigraph terms. A relative IRI, bad blank node label or bad language tag in a query is kept as the SHACL engine's reversible stand-in (`_oxterms.py`). The rewrites render through `sqe/_memtree.py` (no store, so lexical forms survive; a store rewrites `"007"^^xsd:integer`). Running a tree means running the text from `sqe_tree_to_text` (the old `sqe_tree_to_query` that decoded to an rdflib `Query` is gone).
- **The sqe coverage tests are an opt-in set**, left out of a normal run: `pytest tests/sparql/sqe_coverage --sqe-coverage` (about 4 minutes). It runs every W3C SPARQL 1.2 query fixture and 90+ per-feature queries through sqe, comparing with the same query on a `StarLayerGraph`/`StarLayerDataset`. The fixtures sqe cannot round-trip are in `packages/starlayer/tests/sparql/sqe_coverage/sqe_known_gaps.txt` as strict xfails; after a change, refresh it with `python -m tests.sparql.sqe_coverage.test_w3c_through_sqe --regenerate`. Add a feature query to `FEATURES` in `packages/starlayer/tests/sparql/sqe_coverage/test_sqe_features.py` when you add a construct. The same directory holds a Hypothesis suite (random valid queries must parse, render stably and return the same rows), differential suites against plain rdflib and against Oxigraph (the SPARQL 1.2 referee, via `pyoxigraph`), and a shape audit (corrupt each property of rich trees and require the shapes to notice); see the test file names there. Give a new sqe property its own shape and do not declare an `rdfs:domain` on a property several node types share.
- **Run the tests with** `cd packages/starlayer && pytest tests/sparql`. The W3C SPARQL 1.2 syntax fixtures run on the owned parser (`tests/sparql/w3c_sparql12/`), the evaluation fixtures on the original text (`tests/graph/w3c_sparql12/`).

## What is here

- **Purpose.** Represent a SPARQL 1.2 query or rule set as RDF so it can be stored, edited, validated and queried like other RDF data, and parse SPARQL 1.2 text. Execution of SPARQL text is not done here: `StarLayerGraph.query()` / `update()` send the text to Oxigraph (see `graph/CLAUDE.md`).
- **Parsing** (`parse_sparql.py`): the owned recursive-descent parser (a tokenizer and a generic `Node` AST, with the static checks the grammar leaves to prose). `check.py::check_query(text, prefixes=None, *, custom_functions=None, custom_aggregate_functions=None)` returns a `QueryCheck` (`form`, `ok`, `problems` of `QueryProblem(kind, severity, message, line, column)`): the grammar (`syntax`; `prefix` for an undeclared prefix, a warning when no `prefixes=` are given, because the graph the text runs against may declare it, with a placeholder namespace so the rest is still checked, and an error when they are), the `VERSION` directive (`version`: the `FormatError` (kind `"sparql"`, `context="VERSION"`) that `query()` and `update()` raise), Oxigraph on a query run on an empty graph (`engine`; updates, `SERVICE` queries and texts with an undeclared prefix are not run, and `custom_functions=` names the functions the text calls) and the `sqe:` shapes on the tree (`shape`, as warnings: legal SPARQL that is probably a mistake, such as a variable never bound). `StarLayerGraph.check_query(text)` is the same check with the graph's prefixes. It is a check to run before a query, not something `query()` runs.
- **`sqe:`** (`sqe/`): the public "query as RDF" tree, flat and editable, with SHACL shapes for field-level UI validation. `sqe_parse_to_tree` / `sqe_tree_to_text` / `sqe_validate` (the shapes, then, if they conform, Oxigraph on each rendered query; `sqe_parse_to_tree`, `sparql_to_tree` and `sparql_update_to_tree` do not validate: any text the parser understands gives a tree, and `sqe_validate` reports its problems; `check_query` and the SHACL-embedded-query check use the shapes-only `shapes._validate_shapes`) (and `sqe/entailment.py`, the RDF and RDFS query rewrite behind `query(entailment=...)`). Reached as `from starlayer.sparql import sqe`. Design notes: `sqe/vocab.py`.
- **SRL** (`srl.py`, `_srl_ast.py`, `parse_srl.py`, `srl_eval.py`, `srl_semantic_checks.py`, `expr_text.py`, `triple_term.py`): SPARQL Rules (Datalog-style) parsed to an AST (`RuleSet`), converted to and from RDF (`srl:` tree, validated by the `srl:` shapes in `starontology/`), checked for well-formedness, stratified and evaluated. Entry points: `srl.parse_ruleset` (raises `FormatError` kind `"srl"` only for text outside the grammar; checks no §4.2 condition, no shapes and no stratification, so a rule set with a problem still loads, and `srl_validate` on `ruleset_to_tree(rs)` reports all three; `infer`/`query`/`materialize` raise `FormatError` (kind `"srl"`) for a §4.2 breach and `ExecutionError` (kind `"rule"`, context `"stratification"`) for an unorderable set (a damaged `srl:` tree is `FormatError` kind `"srl"` or `"rdf"` too, an import the loader cannot read is `ExecutionError` kind `"import"`, an imported text that is not a rule set `FormatError` kind `"srl"`; no SRL error class of its own, no `ValueError`), `resolve_imports`/`plan` stratify the combined set; no `validate=` parameter; no warning class for `IMPORTS`: `srl_validate` reports them as an `sh:Warning`, `infer`/`query`/`materialize` raise `ExecutionError` kind `"import"` and `plan()` without a loader covers the rules in the document only; `RuleSet.is_resolved`), `RuleSet.infer`, `RuleSet.query` (runs only the rules the goal can depend on, `srl_eval._rules_for_goal`: the rules with a head the goal can match and what they depend on, the whole set still stratified; the goal is one triple pattern as SPARQL text, `"?who ex:ancestorOf ex:carol"`, parsed as a rule body with the graph's prefixes, then the rule set's; a `TriplePattern` is still accepted), `RuleSet.plan`, `RuleSet.materialize` (a `srl_eval.Materialization`, reached as `srl.Materialization`: the rules run once and the evaluation graph kept; `query(goal)` matches on it, `inferred` is the `infer()` graph, `stale` compares the write count of the graph's store (`union.version_of(store).stamp()`) with the one taken before the run, so a write to another store does not make it stale, and a write to another graph of the same store does, `refresh()` runs again, `close()` drops it; a snapshot, never refreshed on its own). Evaluation matches rule bodies with SPARQL on a `StarLayerGraph`, with the spec's pseudocode for dependencies, stratification and `WHERE GROUND`. The general rules of a stratum run to a fixpoint from each round's new triples, not by re-evaluating every rule over the whole graph (`srl_eval._run_to_fixpoint`: a named delta graph in the evaluation store, one variant of a rule per body pattern that can match a derived triple). A rule made of triple patterns, filters, assignments and negations of triple patterns (a head with blank nodes is fine) runs in the store as one `INSERT ... WHERE` (`_store_plan`; a filter, assignment or negation may use only variables bound before it, and an assignment that is an error drops its solution, which needs a group closed by `FILTER(BOUND(?x))` because a filter applies to its whole group; a rule with `BNODE()`, `WHERE GROUND`, aggregation or a blank node inside a head triple term uses the element-by-element evaluation). A stratum whose one repeating rule is a closure Oxigraph computes itself (`q(x,z) <- q(x,y), q(y,z)`, `q <- q, p` or `q <- p, q`, `_closure_of`) is one update with a property path (`q+`, or `q` then `p*`) after the stratum's other rules have run once, not rounds. In any other recursive stratum the rule writes into a candidate graph and the new triples of a round are found in Python or by a `MINUS` update by size (`_Evaluation.commit`, `_MINUS_FROM`); every rule in a round reads the graph as it was at the start of the round. A pass with nothing to repeat (a run-once rule, or a stratum no rule of which feeds another: `_derive_once`) lets a rule with one head triple, or with a blank node in its head, write straight into the evaluation graph and the inferred graph (`_StorePlan.direct`). The base graph is copied once, into the evaluation graph (`_Evaluation`), whose store keeps everything derived in a named graph; `RuleSet.query` matches on that graph itself. `tests/sparql/unit/test_srl_semi_naive.py` and `test_srl_single_pass.py` compare each way with full rounds and with the element-by-element evaluation, and `test_srl_random_rule_sets.py` does so on random rule sets (`SRL_FUZZ_SEEDS=5000` for a long hunt). `IMPORTS` need a caller-supplied loader. Only `RuleSet` and `TriplePattern` of the AST are public.
- **`relevant_subgraph`** (`relevant.py`; reached as `relevant_subgraph(query)` on a graph or a dataset, which adds its prefixes, and not exported from `starlayer.sparql`): given a graph and a SELECT, ASK or CONSTRUCT query, the triples the answer depends on, so the query gives the same answer on them. Oxigraph cannot report reads, so it runs `CONSTRUCT` queries built from the query's own patterns over its own `WHERE` group (the supports), plus, for `FILTER (NOT) EXISTS` and `MINUS`, the matches of the excluded group over the relaxed group (the evidence of exclusion). A property path contributes the edges a walk from its subject to its object takes (a guard query spells the walk out), and a zero-length walk every triple that mentions the node; a sub-select is a query of its own; a filter testing `BOUND` / `COALESCE` / `IF` is relaxed like a negation. Blank nodes (`_:x`, `[ ... ]`) and collections (`( ... )`) are rewritten into variables and triples first. `GRAPH` and `EXISTS` outside the `WHERE` group fall back to every triple matching a pattern (larger, never smaller). `SERVICE` raises `ValueError` (the answer depends on a remote graph). A `StarLayerDataset` gives a `StarLayerDataset` of quads (`relevant_quads`): each support query tags what it read with the graph (`graph _QUAD_MARK <<( s p o )>>`, a triple term being an object only): `GRAPH <g>` / `GRAPH ?g` the graph it matched in, a pattern outside any `GRAPH` block every graph that holds the triple under `default_union` (or the `FROM` graphs). A negation or a property path inside a `GRAPH` block is read in that graph (the evidence query is wrapped in `GRAPH <g> { }`); a sub-select under `FROM` is the pattern fallback. `tests/sparql/unit/test_relevant_subgraph.py` checks it; a random check of 1000 datasets and queries with `GRAPH`, `OPTIONAL`, `UNION`, paths and negations gave the same answer on the result every time. Reproducible: it never picks between derivations (all paths, all witnesses, all triples that make a node exist stay). Checked against random queries and graphs in `tests/sparql/unit/test_relevant_subgraph.py`. `extract_subgraph()` uses it for `sh:select`, `sh:sparql` and SPARQL-based components.
- **`StarQuery`** (`star_query.py`): a syntax-checked query plus the per-call options of `StarLayerGraph.query()`, to run on several graphs.
- **Shared vocabulary** (`vocab.py`, `expr_families.py`, `expr_validation.py`): the `sqe:` / `spexpr:` terms and the shapes and RDFS closure `sqe` and `srl` both validate with.

## Tests

- `tests/sparql/`: `unit/` (one file per area), `sqe_coverage/` (opt-in, see the rule above), `srl_conformance/`, `parse_sparql_conformance/`, `hunt/` and the pinned W3C suites `w3c_sparql11/` and `w3c_sparql12/` (the syntax fixtures, run on the owned parser).
- A "conforms" test is not an execution test: every new `sqe:` query shape needs a test that renders it back to text, runs the text and compares the result with an independent engine (Oxigraph, or rdflib where it has an oracle).
- Past decisions are in git history (`git log -- packages/starlayer/starlayer/sparql`) and `docs/working/`.
