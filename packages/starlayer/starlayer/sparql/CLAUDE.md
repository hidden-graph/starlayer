# CLAUDE.md

Project-specific instructions for Claude Code sessions working in this repo.

## Rules that bite

- **`sqe:` is the public "SPARQL query as RDF" vocabulary** (a flat, editable tree from the parser's syntax tree). The internal `salg:` algebra encoding, its shapes and the rdflib algebra machinery behind it were retired at E4; do not reintroduce `salg:` terms.
- **No rdflib in this package.** Everything here runs on pyoxigraph terms: the owned parser (`parse_sparql.py`), `sqe:` trees (`StarLayerGraph`s), SRL (`srl.py`, `_srl_ast.py`, `parse_srl.py`, `srl_eval.py`, `srl_semantic_checks.py`) and `StarQuery`. rdflib is reached only by the bridge (`graph/oxgraph/_rdflib_bridge.py`), lazily, when a caller passes an rdflib graph to SRL (`RuleSet.infer` / `.query`, `ruleset_to_tree(graph=...)`, `tree_to_ruleset`) or `StarQuery.run`; those raise the clear "needs rdflib" ImportError without it. `tests/test_core_without_rdflib.py` runs SRL with rdflib blocked.
- **Execution is Oxigraph's.** `StarLayerGraph.query()` / `update()` hand SPARQL 1.2 text to Oxigraph. SRL evaluates a rule body as one SPARQL `SELECT` per run of triple patterns, and a filter or `SET` expression as text with the solution's variables substituted, on `StarLayerGraph`s.
- **Triple terms in rules are `TripleTermNode`** (`triple_term.py`), a comparable, hashable parser `Node` of kind `TripleTerm`; an expression is the parser's own `Node` tree (`ExprNode`, structural equality) or a bare term. Never a pyoxigraph `Triple` in a pattern, which could not hold a variable. A triple term can never be the subject or predicate of another triple term or of a triple (`InvalidTripleTermError`; for rule sets the `triple_term_in_subject` / `triple_term_in_predicate` well-formedness issues).
- **A bare Python `str` in an encoded tree is `Literal(text, datatype=spexpr:PlainString)`; a variable is `Literal(name, datatype=spexpr:Variable)`.** The encoder (`parse_sparql._Encoder`) does both; `srl.py` reuses it for the leaves of the `srl:` tree.
- **An `srl:` tree is read back by rendering each expression node to text and parsing the text** (`srl._decode_expr`), so the decoded rule set equals the one written, up to the literal forms the Oxigraph store keeps (`"9.0"^^xsd:decimal` comes back `"9"`).
- **The RDFS closure behind `sqe_validate` and `srl_validate` is native** (`expr_validation.rdfs_schema` / `rdfs_entailed_copy`); the general closure behind `infer()` runs on owlrl and so on rdflib.
- **SRL (SPARQL Rules).** `parse_ruleset()` validates against the `srl:` shapes by default (about 140 ms; `validate=False` skips). `evaldata` is the spec's polarity: `WHERE DATA` and `NOT DATA` match the base graph. `IMPORTS` need a caller-supplied loader and nothing is fetched on its own. `RuleSet.plan()` shows the rule order. Aggregation and SRL-to-SPARQL are waiting on the spec. The SRL conformance suite (`tests/sparql/srl_conformance`, 929 tests, about 10 minutes) is opt-in: `--srl-conformance`.
- **The sqe path is pyoxigraph and needs no rdflib.** `parse_sparql.py` builds pyoxigraph terms; `sqe_parse_to_tree` writes a `StarLayerGraph`; `sqe_tree_to_text`, `sqe_validate`, `rewrite_exists_text` and the RDF / RDFS entailment rewrite read it with pyoxigraph terms. A relative IRI, bad blank node label or bad language tag in a query is kept as the SHACL engine's reversible stand-in (`_oxterms.py`). The rewrites render through `sqe/_memtree.py` (no store, so lexical forms survive; a store rewrites `"007"^^xsd:integer`). Running a tree means running the text from `sqe_tree_to_text` (the old `sqe_tree_to_query` that decoded to an rdflib `Query` is gone).
- **The sqe coverage tests are an opt-in set**, left out of a normal run: `pytest tests/sparql/sqe_coverage --sqe-coverage` (about 4 minutes). It runs every W3C SPARQL 1.2 query fixture and 90+ per-feature queries through sqe, comparing with the same query on a `StarLayerGraph`/`StarLayerDataset`. The fixtures sqe cannot round-trip are in `packages/starlayer/tests/sparql/sqe_coverage/sqe_known_gaps.txt` as strict xfails; after a change, refresh it with `python -m tests.sparql.sqe_coverage.test_w3c_through_sqe --regenerate`. Add a feature query to `FEATURES` in `packages/starlayer/tests/sparql/sqe_coverage/test_sqe_features.py` when you add a construct. The same directory holds a Hypothesis suite (random valid queries must parse, render stably and return the same rows), differential suites against plain rdflib and against Oxigraph (the SPARQL 1.2 referee, via `pyoxigraph`), and a shape audit (corrupt each property of rich trees and require the shapes to notice); see the test file names there. Give a new sqe property its own shape and do not declare an `rdfs:domain` on a property several node types share.
- **Run the tests with** `cd packages/starlayer && pytest tests/sparql`. The W3C SPARQL 1.2 syntax fixtures run on the owned parser (`tests/sparql/w3c_sparql12/`), the evaluation fixtures on the original text (`tests/graph/w3c_sparql12/`).

## What is here

- **Purpose.** Represent a SPARQL 1.2 query or rule set as RDF so it can be stored, edited, validated and queried like other RDF data, and parse SPARQL 1.2 text. Execution of SPARQL text is not done here: `StarLayerGraph.query()` / `update()` send the text to Oxigraph (see `graph/CLAUDE.md`).
- **Parsing** (`parse_sparql.py`): the owned recursive-descent parser (a tokenizer and a generic `Node` AST, with the static checks the grammar leaves to prose). `check.py::check_query` says whether a text is valid SPARQL 1.2 and what is wrong if not.
- **`sqe:`** (`sqe/`): the public "query as RDF" tree, flat and editable, with SHACL shapes for field-level UI validation. `sqe_parse_to_tree` / `sqe_tree_to_text` / `sqe_validate` (and `sqe/entailment.py`, the RDF and RDFS query rewrite behind `query(entailment=...)`). Reached as `from starlayer.sparql import sqe`. Design notes: `sqe/vocab.py`.
- **SRL** (`srl.py`, `_srl_ast.py`, `parse_srl.py`, `srl_eval.py`, `srl_semantic_checks.py`, `expr_text.py`, `triple_term.py`): SPARQL Rules (Datalog-style) parsed to an AST (`RuleSet`), converted to and from RDF (`srl:` tree, validated by the `srl:` shapes in `starontology/`), checked for well-formedness, stratified and evaluated. Entry points: `srl.parse_ruleset`, `RuleSet.infer`, `RuleSet.query`, `RuleSet.plan`. Evaluation matches rule bodies with SPARQL on a `StarLayerGraph`, with the spec's pseudocode for dependencies, stratification and `WHERE DATA`. `IMPORTS` need a caller-supplied loader. Only `RuleSet` and `TriplePattern` of the AST are public.
- **`relevant_subgraph`** (`relevant.py`): given a graph and a SELECT, ASK or CONSTRUCT query, the triples the answer depends on, so the query gives the same answer on them. Oxigraph cannot report reads, so it runs `CONSTRUCT` queries built from the query's own patterns over its own `WHERE` group (the supports), plus, for `FILTER (NOT) EXISTS` and `MINUS`, the matches of the excluded group over the relaxed group (the evidence of exclusion). A property path contributes the edges a walk from its subject to its object takes (a guard query spells the walk out), and a zero-length walk every triple that mentions the node; a sub-select is a query of its own; a filter testing `BOUND` / `COALESCE` / `IF` is relaxed like a negation. Blank nodes (`_:x`, `[ ... ]`) and collections (`( ... )`) are rewritten into variables and triples first. `GRAPH`, `SERVICE` and `EXISTS` outside the `WHERE` group fall back to every triple matching a pattern (larger, never smaller). Reproducible: it never picks between derivations (all paths, all witnesses, all triples that make a node exist stay). Checked against random queries and graphs in `tests/sparql/unit/test_relevant_subgraph.py`. `extract_subgraph()` uses it for `sh:select`, `sh:sparql` and SPARQL-based components.
- **`StarQuery`** (`star_query.py`): a syntax-checked query plus the per-call options of `StarLayerGraph.query()`, to run on several graphs, or on an `EntailmentSession` (which applies its own regime, so the query binds none).
- **Shared vocabulary** (`vocab.py`, `expr_families.py`, `expr_validation.py`): the `sqe:` / `spexpr:` terms and the shapes and RDFS closure `sqe` and `srl` both validate with.

## Tests

- `tests/sparql/`: `unit/` (one file per area), `sqe_coverage/` (opt-in, see the rule above), `srl_conformance/`, `parse_sparql_conformance/`, `hunt/` and the pinned W3C suites `w3c_sparql11/` and `w3c_sparql12/` (the syntax fixtures, run on the owned parser).
- A "conforms" test is not an execution test: every new `sqe:` query shape needs a test that renders it back to text, runs the text and compares the result with an independent engine (Oxigraph, or rdflib where it has an oracle).
- Past decisions are in git history (`git log -- packages/starlayer/starlayer/sparql`) and `docs/working/`.
