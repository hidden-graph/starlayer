# Changelog

## Unreleased

- SRL: `IMPORTS` are supported through a caller-supplied loader: `srl.resolve_imports(ruleset, loader)` and an `imports_loader=` argument on `RuleSet.infer()`, `.query()` and `.plan()`. Each document is read once; rules and `DATA` are merged as in the spec's Appendix B; there is no default loader, and without one a rule set with imports is rejected as before. New `SRLImportError`.
- SRL: rule bodies (and `NOT` bodies) accept the property paths the spec allows, `/` and `^`, expanded into plain triple patterns when the rule is built; any other path operator raises `SRLParseError`.
- SRL: RDF 1.2 triple terms (`<<( s p o )>>`), reified triples, reifiers and annotations now work in rule bodies, heads and DATA blocks, along with `,` object lists, `[ ]` property lists and collections, because the triple groups use rdflib's `TriplesSameSubject` (shared with the SPARQL 1.2 grammar). Matching a triple term runs the pattern as a SPARQL 1.2 query over a `StarLayerGraph`. `infer()` on a `StarLayerGraph` holding triple terms no longer crashes. A triple term as a subject and a variable in a DATA block are rejected at parse time.
- SRL: `parse_ruleset()` now also validates the rule set against the `srl:` SHACL shapes and raises `SRLParseError` if it does not conform (about 140 ms per parse; pass `validate=False` to skip). The shapes graphs are cached.
- SRL: brought in line with the 2026-10-14 draft where it is finished. `WHERE DATA` rules and `NOT DATA` negations no longer add rule dependencies (the spec's own Examples 9 and 10 raised `StratificationError` before); a blank node in a body pattern is treated as a variable when working out dependencies; a head template for a triple term containing a variable makes a rule run-once; an aggregate inside `FILTER` or `SET` is rejected at parse time instead of crashing at `infer()`. Added `RuleSet.plan()`. The rule/negation flag is now the spec's `evaldata` (true = match the evaluation graph) instead of `data`, and the RDF properties `srl:ruleData`/`srl:negationData` are now `srl:ruleEvaldata`/`srl:negationEvaldata` (no compatibility layer). Aggregation (Issue 840) is not implemented: the draft has no grammar for it yet.
- Added full SRL support (`WD-sparql12-rl-20260919`): a real pyparsing grammar (`srl_grammar.py`/`srl_ast.py`), a `srl:` AST-as-RDF namespace with a full round trip (`srl_vocab.py`/`srl_to_rdf.py`/`srl_from_rdf.py`), structural SHACL shapes (`ontology/srl_shapes.py`, registered as `srl_owl`/`srl_shacl`), the §4.2 well-formedness check (`srl_semantic_checks.py`), and a stratified Datalog evaluation engine (`srl_eval.py`) verified end to end against the spec's own §6.6 worked example.
