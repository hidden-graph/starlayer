# Changelog

## Unreleased

### Added

- **`format="manchester"` (alias `"omn"`) for `StarLayerGraph.parse()`.** A native, pure-Python parser for OWL 2 Manchester Syntax (`starlayergraph/parsers/manchester_parser.py`) - no Java/OWL API dependency, consistent with every other format this project reads. Covers all frame types (`Class:`, `ObjectProperty:`, `DataProperty:`, `AnnotationProperty:`, `Individual:`, `Datatype:`) and their clauses, the full class-expression grammar (`and`/`or`/`not`/`that`, `some`/`only`/`onlysome`/`value`/`Self`, qualified and unqualified `min`/`max`/`exactly`, `{...}` enumeration, `inverse`), data ranges with facet restrictions (`xsd:int[>= 0, <= 150]`, DataOneOf, data `and`/`or`), property chains, `HasKey:`, `DisjointUnionOf:`, positive and negative `Facts:`, frame-level `Annotations:`, and every top-level Misc axiom - mapped to RDF per the OWL 2 Mapping to RDF Graphs spec. Deliberately unsupported (raising `ManchesterSyntaxError`, never silently dropped or mis-parsed): SWRL `Rule:`, inline per-axiom `Annotations:` (needs `owl:Axiom` reification - the one significant remaining gap), and a couple of reserved-but-dead OWL API keywords. Full conformance tracking, including what's deliberately not matched and why, in `docs/manchester_syntax_gap_analysis.md` - derived by decompiling OWL API 5.1.20's own keyword table plus empirical cross-checks against its real parser (an external, uncommitted oracle - not a project dependency) via `starlayergraph.compare.isomorphic()`. Tests: `tests/unit/test_manchester_parser.py`.

### Fixed

- **Blank-node label collision across repeated `StarLayerGraph.parse()` calls.** Turtle 1.2 parsing (`format="turtle12"`/`"longturtle12"`) minted anonymous-node labels (`_:sl_N`, `_:si_N`) from a counter that restarted at 0 on every call. Calling `.parse()` more than once on the same graph, where more than one call's Turtle body contained an anonymous `[ ... ]` node, could silently merge unrelated blank nodes that happened to land on the same number into a single node, corrupting the graph. Found live while building a guide example that used two separate `.parse()` calls; every call site elsewhere in this codebase happened to use a single call, which is why this had never surfaced. Fixed by seeding the counter with a random per-call offset (`starlayergraph/parsers/turtle_parser.py`) so labels from different calls can never collide. Regression test: `tests/unit/test_turtle_parser.py::TestBlankNodeUniquenessAcrossCalls`.
