# StarLayer Audit Report

2026-10-23 · John Clements

## Scope & method

Read-only audit of the `hidden-graph/starlayer` repository at commit `489f310` (main, clean tree, 2026-10-23). No code, docs or configuration were changed. Method: repository structure and history review; the checks CI runs (ruff, the fast pytest tier, `scripts/build.py --check`); a read of the public API surface, package layout, test organization, guides and CI workflows; and targeted code reads in `graph/`, `sparql/` and `shacl/`. Observations are grouped by area below; prioritized recommendations are at the end.

## Repository overview

StarLayer is a Python layer over rdflib and pySHACL that adds the RDF 1.2 / SPARQL 1.2 / SHACL 1.2 draft features (triple terms, reifiers, annotations, direction-tagged literals, SPARQL 1.2 queries, SHACL 1.2 validation/rules/UI widget selection). It is explicitly transitional: the README states it will be retired once rdflib and pySHACL support the final 1.2 specs. The project is young and fast-moving — 246 commits since 2026-08-12 (about 10 weeks), all on `main` via PRs.

| Component | Files | Lines | Role |
| --- | --- | --- | --- |
| `starlayer/graph/` | 49 | ~19,900 | RDF 1.2 graphs/datasets, parsers/serializers, Oxigraph/Fuseki/SQLAlchemy backends, inference, canonical hashing |
| `starlayer/sparql/` | 38 | ~11,800 | SPARQL 1.2 parsing/eval, queries-as-RDF (`sqe:`), SRL rules |
| `starlayer/shacl/` | 19 | ~13,600 | SHACL 1.2 validation, rules, node expressions, subgraph extraction, UI forms |
| `starlayer/codekg/` | 13 | ~3,100 | Code knowledge graph tooling (repo-only, not shipped) |
| `starlayer/starontology/` | 3 | ~2,200 | Bundled ontologies and shapes |
| `tests/` | 202 test files | ~52,900 | Roughly 1:1 test-to-code ratio by volume |

Notable: the repo documents itself for AI agents (a root `AGENTS.md`, per-package `CLAUDE.md` files with a "Rules that bite" convention) and maintains a queryable code knowledge graph (`codekg.trig`) with 24 named queries, a build stamp, and staleness reporting — an unusually deliberate self-description layer for a project this young.

## Architecture & API observations

**Strengths.** The top-level API is deliberately tiny (`StarLayerGraph`, `StarLayerDataset`, `StarShaclSchema`, `StarQuery`). Backend quirks are isolated in dedicated rewriting modules (`graph/backends/skolem_semantics.py` for Fuseki blank nodes, `dirlang_equality.py` for an Oxigraph crash). All runtime patches are idempotent via sentinel attributes. A 317-line `graph/graph/_rdflib_inherited_contract.py` snapshots the inherited rdflib API to catch upstream drift. And the per-package `CLAUDE.md` "Rules that bite" blocks honestly record every fragile spot — rare and valuable.

**Monkey-patching is the primary extension mechanism, and it is process-global.** `import starlayer.graph` applies 14 patches to rdflib's SPARQL engine (`graph/query/evaluate_patches.py`, `operator_patches.py`, `result_patches.py`, `algebra_translator_patches.py`); `sparql/_grammar12.py:797` rewrites rdflib's shared pyparsing grammar in place; `shacl/validator.py` patches about 10 pySHACL internals (`Shape.validate`, `focus_nodes`, rule `apply`, …). Subclassing is minor by comparison. Consequence: importing StarLayer changes the behavior of plain rdflib and pySHACL for everything else in the same process, and correctness is pinned to specific upstream versions (pySHACL is verified against 0.40.x only, per `pyproject.toml`). For a self-declared transitional shim this is a defensible strategy, but it is the project's single largest structural risk and deserves to be stated in the README, not only in internal notes.

**Layering is mutual, not stacked.** All three core packages import each other (graph↔sparql, graph↔shacl, sparql↔shacl — e.g. graph's query path imports sparql's parser at `graph/query/query_cache.py:39`, and `graph/graph/shape_derivation.py:16` itself admits a "layering mistake"). Several lazy imports exist only to dodge circular-import deadlocks, and private names cross package boundaries (`starlayer_graph.py:2474` imports `sparql.lower_rdf11._AlgebraTranslator11`; `starontology/manchester.py:549` imports `_Cursor`/`_tokenize` from the graph parser). The SPARQL 1.2 parser/lowering that graph depends on would naturally live in graph or a shared core.

**Public-surface inconsistencies.**
- `sparql/__init__.py` exports `SALG`, which sparql's own CLAUDE.md calls internal, while the public `SQE` vocabulary is *not* exported at that level.
- Two parallel query entry points with clashing conventions: rdflib-style `prepareQuery` from graph vs `prepare_query_12` from sparql.
- `graph/query/__init__.py` exports rdflib's internal `CompValue`; `sparql/salg/expr_families.py` puts a private `_EXPR_NODE_FAMILY` in `__all__`; `shacl/__init__.py:51-69` mixes the documented API with normalization/adapter plumbing whose encoding is documented as private.

**No store abstraction.** In-memory vs native is a boolean `_is_native` checked ~35 times in `starlayer_graph.py` (the CLAUDE.md rule "a change usually needs a twin" confirms the cost); `graph/backends/native.py:423` dispatches on `type(store).__name__ == 'OxigraphStore'` and duck-types HTTP endpoints via `getattr`. A small store protocol would collapse much of this branching.

**Oversized modules.** `shacl/validator.py` (5,925 lines: the schema API, every processing mode, and the pySHACL patches), `graph/graph/starlayer_graph.py` (3,703 lines: both storage paths, querying, remote decomposition, imports), `shacl/native_components.py` (3,233). Also: two distinct triple-term encodings (graph's `tt:` and shacl's private `urn:starlayer:tt:`), two different `conformance.py` files, global mutable encoder hooks shared by `sqe`/`salg` (`_NS_OVERRIDES`, `_ENCODE_HOOK`), and the stuttering `graph/graph/` path.

## Code quality observations

Overall the code is careful and heavily documented, with no bare `except:` anywhere and good use of `ContextVar` for per-call state. Four findings stand out, the first two serious.

**1. Patch failures are silent.** Around 29 patch installers set a `_*_patch_status = False` flag inside `except Exception` with no warning or log (confirmed: `shacl/validator.py:4160, 4262, 4444, 4856, 4987, 5186, 5274, 5361` and more in `graph/query/operator_patches.py`; `validator.py` contains no `warnings.warn` or logger at all). If an rdflib or pySHACL upgrade changes an internal, the correctness patches switch off without a trace and *wrong query or validation results come back silently*. Only one test inspects a status flag. For a library whose whole value is patched correctness, this is the highest-risk code-level finding.

**2. `shacl/validator.py` contains two drifted copies of the validation pipeline.** Sixteen `StarShaclSchema` methods (~1,350 lines, lines 417–1750) have module-level twins of the same names (lines 2191–3900), and neither copy calls the other (confirmed: e.g. `_augment_shapes_with_new_target_types` at `:973` and `:2191`, `validate` at `:417` and `:3202`). Similarity ranges from 0.96 down to 0.39 — they have already diverged (e.g. the twins at `:1050` vs `:2263` gather implicit-class candidates differently). This contradicts shacl's own CLAUDE.md, which says the bare `validate()` constructs a throwaway instance. Every future fix must be made twice or the two entry points disagree.

**3. Errors swallowed into empty results.** Of 93 `except Exception` blocks, 17 silently return `[]`/`None`/`False` or `pass`. The riskiest make SHACL evaluation incomplete rather than failed: value-node evaluation returns `[]` on error (`validator.py:5046, 5057, 5095`), a rule's failed query produces no triples (`:5790`), a failed SPARQL constraint is skipped per focus node (`native_components.py:351`), target expressions are dropped (`validator.py:1070, 2283`). A probe failure in `graph/backends/native.py:452,477` — including a transient network error — is permanently cached in the module dict `_BNODE_ID_STABILITY` as "not stable". The library has no logger, so none of this is observable.

**4. Typing is uneven and unchecked.** 74% of the 1,508 functions annotate returns, but it varies from 94% (shacl) down to 30% (graph), `validator.py` leans on `Any`, and there are 56 `# type: ignore` comments. Three `py.typed` markers ship, yet no mypy/pyright config or CI step exists — the typed-package claim is unverified (also noted under Packaging).

Smaller points:

- **Upstream workarounds are well-curated but weakly cross-referenced in code**: 28 issues tracked in `codekg/curated/upstream-issues.ttl` (rdflib 18, pySHACL 6, Fuseki 2, Oxigraph 2; 25 worked around), all 25 code identifiers valid — but only ~4 code sites cite their issue id, and two citations are stale (`evaluate_patches.py:10,102` cite "issue 5" where the TTL says rdflib-3; `:1270,1286` cite "Issue 9" for what the TTL records as issue 5).
- Docstrings follow the "why" convention well, but only 38 in the whole codebase document what is raised, and coverage dips in `native_components.py` (28 of 109 public functions) and `lower_rdf11.py`.
- Minor duplication: `_collect_tt`/`_fmt_collect` repeated between `turtle12.py` and `longturtle12.py`; a non-thread-safe module-level counter at `evaluate_patches.py:1275`.
- Private rdflib imports beyond the patches (`_ebv`, `_addVars`, `_traverseAgg`, `_join`, `_eval`) widen the upstream-version exposure.

## Testing observations

The suite is healthy and unusually well-tiered. The fast tier passes clean at HEAD: **4,065 passed, 294 skipped, 15 xfailed, 3,786 deselected in 2m52s** (run locally on Python 3.14 — so 3.14 does work, it is just not in the CI matrix).

- **Volume and shape**: ~3,000 test functions in 202 files (~52,900 lines, roughly 1:1 with source by volume), split per area (shacl 74 files, graph 57, sparql 44, starontology 10, codekg 12) with markers applied automatically from the directory.
- **Tiering is deliberate**: a fast default tier; `--deferred` for committed-data checks CI always runs; opt-in slow groups (`--store-matrix`, `--sqe-coverage`, `--srl-stratification`, `--manchester-conformance`, `--codekg-queries`) each documented in `conftest.py` and in `pyproject.toml` marker descriptions.
- **Conformance anchoring**: W3C SPARQL 1.2 and SHACL 1.2 suites are synced in (`scripts/sync_w3c_shacl12_suite.py`) and cross-checked, and the stated oracle discipline is to compare behavior against plain rdflib/pySHACL.
- **Docs are executable**: meta-tests verify the README example (`test_readme_example.py`), the claims in AGENTS.md (`test_agents_md.py`), re-export consistency (`test_reexports.py`) and the test-group wiring itself (`test_test_groups.py`).
- **Benchmarks** have committed baselines with a daily scheduled regression check.

Gaps:

- **Property-based testing is thin**: Hypothesis is a test dependency but appears in only 4 of 202 test files, in a codebase dominated by hand-written parsers and serializers (turtle, trig, ntriples, Manchester) — the single best fuzz target this repo has.
- **No coverage measurement** (also noted under Packaging): with 3,786 tests deselected by default and heavy skip logic, nobody can currently see which of the ~50k source lines the fast tier actually exercises.
- **Fuseki integration is manual-only** (documented honestly in the workflow), so the Fuseki skolemization/rewriting code paths are not exercised by CI at all.
- **478 warnings in the fast run**, mostly rdflib deprecation warnings (`Dataset.default_context`, `ConjunctiveGraph`, `Dataset.contexts`). For a library whose premise is tracking upstream, these are early notice of rdflib 8 breakage and worth triaging rather than accumulating.

## Documentation observations

Documentation is a clear strength, with one automation gap.

- **Guides**: 25 numbered Jupyter notebooks (`docs/guides/`) cover getting started through graphs, inference, SPARQL, SHACL (including node expressions, rules, UI, profiling, subgraph extraction), ontologies, serialization, backends and canonical hashing, with an index, a style guide and a version manifest.
- **Generated reference**: API overview, full API reference, functionality overview and query catalogue are generated from the code knowledge graph, and CI fails if a committed copy no longer matches its build (`scripts/build.py --check`).
- **Rot checks are automated and currently clean**: `check_docs.py` verifies every relative link and anchor, the guide index, cell ids, and that every file named in a "Rules that bite" block still exists; `check_notebook_links.py` verifies the 32 curated notebook-to-code links. Both run inside the CI build check and both pass today.
- **Upstream-issues dossiers**: per-project write-ups (rdflib, pySHACL, Oxigraph, Fuseki) with minimal repros, cross-referenced from a curated `upstream-issues.ttl` so workarounds are queryable from the KG.
- **Gap — notebooks are never re-executed automatically.** CI checks the guides' links and index, not their behavior: a library change that alters a cell's output (or breaks a cell) is only caught when someone re-runs the notebook by hand. With 25 notebooks this is the most likely place for silent drift.
- **Minor**: the code KG lags `main` by 9 commits at audit time. That is by design (rebuilt on demand, staleness self-reported on every query), but it means generated reference docs can describe code slightly behind HEAD between rebuilds.
- `docs/working/` mixes archived material with live notes; the `archive/` convention is honored by the checkers (skipped), which keeps old copies from rotting the checks.

## Packaging, CI & tooling observations

Packaging and CI are unusually well-reasoned — the `pyproject.toml` and workflows carry inline justifications for nearly every non-obvious choice (the pySHACL version pin, the setuptools<81 pin for rdflib-sqlalchemy, why Fuseki is not a CI service container, why benchmarks never gate PRs). Specifics:

- **Lint**: ruff with a deliberate rule selection (pyflakes, bugbear, isort, pyupgrade) and documented per-file ignores; `ruff check packages/` passes clean at HEAD.
- **CI matrix**: tests on Python 3.10–3.13 with an Oxigraph service container, running the fast tier plus `--deferred` plus the integration marker (Fuseki-only tests self-skip). Generated-file currency is a separate CI job.
- **Benchmarks**: daily scheduled runs (never on PR, with the noise rationale written down) checked against committed baselines by `scripts/check_benchmark_regression.py`.
- **Distribution**: install is `pip install git+…` only — version is a static `0.1.0`, there is no PyPI release, no publish workflow, no CHANGELOG, and no git tags, so downstream users cannot pin anything finer than a commit SHA. For a library that tracks moving draft specs this matters: behavior can change under a plain `git+` install with no signal.
- **Mismatch**: classifiers claim Python 3.14 support but the CI matrix stops at 3.13, so 3.14 is advertised untested.
- **Typing gate missing**: the package ships `py.typed` (annotations are presented as part of the public contract) but no type checker runs in CI or is configured in `pyproject.toml`, so annotation regressions reach users unchecked.
- **No coverage measurement**: the suite is large, but nothing records line/branch coverage, so untested regions are invisible.
- **Reproducibility**: a `uv.lock` is committed but CI installs with bare `pip`, so the lock file is dev-convenience only and CI runs float on latest rdflib/pySHACL — a reasonable early-warning choice for an upstream-tracking library, but worth stating as policy.

## Recommendations

Nothing was changed in this audit. Each item below can become a GitHub issue (the repo's own convention) on request. Priorities weigh the project's stated transitional nature: structural rewrites are ranked below correctness-visibility work, since the library plans to retire when upstream catches up.

**High — correctness visibility (small effort, large risk reduction)**

1. **Make patch failures loud.** Emit `warnings.warn` whenever a `_*_patch_status` flag goes `False`, and add one deferred test asserting every status flag is `True`. Today an upstream upgrade can silently disable the correctness fixes that are the library's reason to exist.
2. **Merge the two validation pipelines in `shacl/validator.py`.** Make the module-level functions thin wrappers over the `StarShaclSchema` methods (as shacl's CLAUDE.md already describes the intent), then reconcile the places that have drifted (e.g. `:1050` vs `:2263`).
3. **Adopt an error-visibility policy.** Add a library logger; log (at least debug-level) every `except Exception` that currently degrades silently into `[]`/skip; stop permanently caching transient probe failures in `_BNODE_ID_STABILITY` (retry, or cache with a distinct "probe failed" state).
4. **Type-check in CI.** Add pyright or mypy (basic mode) starting with `shacl/` (already 94% annotated), or stop shipping `py.typed` until it is checked.

**Medium — release and CI hygiene**

5. **Give users something to pin.** Tag versions (even `v0.1.x` git tags with a short CHANGELOG); bump `version` when behavior changes. A spec-tracking library installed from `git+` moves under its users otherwise.
6. **Align the Python support claim**: add 3.14 to the CI matrix (it passes locally) or drop the classifier.
7. **Measure coverage** in one CI job (`pytest-cov`, report-only) so the effect of the heavy deselect/skip tiering is visible.
8. **Re-execute the guide notebooks on a schedule** (e.g. a weekly `nbclient` job like the benchmark workflow) — the only part of the docs not machine-checked today.
9. **Triage the rdflib deprecation warnings** now (478 warnings in the fast tier); turn the known ones into explicit `filterwarnings` entries so new ones stand out. They are the early signal for rdflib 8.

**Lower — surface and structure (do opportunistically)**

10. **Tidy the public surface**: export `SQE` from `starlayer.sparql` and stop exporting `SALG` (documented internal); pick one of `prepareQuery` / `prepare_query_12` as the recommended path; drop `CompValue` and `_EXPR_NODE_FAMILY` from `__all__`.
11. **State the process-global patching in the README.** Users embedding StarLayer next to plain rdflib/pySHACL code should learn this from the front page, not from internal notes.
12. **Cite issue ids at workaround sites** and fix the two stale citations in `evaluate_patches.py` ("issue 5" → rdflib-3; "Issue 9" → issue 5).
13. **Introduce a small store protocol** to replace the ~35 `_is_native` branches and the `type(store).__name__` dispatch — worthwhile only if the library's horizon extends; otherwise leave it.
14. **Spend Hypothesis where it pays**: property-based round-trip tests for the hand-written parsers/serializers (turtle12, trig12, ntriples12, Manchester), which today have almost no fuzzing.

**What is genuinely good and worth keeping as-is**: the tiny top-level API; the test tiering with self-documenting markers; executable docs (README and AGENTS.md claims under test); the curated upstream-issues graph; the self-describing code KG with staleness stamps; CI/pyproject decisions with their rationale written down; quirk isolation per backend; and the "Rules that bite" convention.
