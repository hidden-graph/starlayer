# Bug hunt on `shacl-engine`, November 2026

Whole library except codeKG, on the `shacl-engine` branch. Each of 15 areas went through the same pipeline: two hunters with
different approaches, two independent verifiers per finding (both had to find a real bug), a fixer in an isolated worktree
(failing test first, one commit per bug), then an adversarial reviewer. Everything is merged locally; nothing is pushed.
The baseline is the tag/branch `hunt-baseline`; `git log hunt-baseline..HEAD` lists the work (each area is one
`Merge hunt fixes: <area>` commit).

## Decisions needed

1. **Scratch graph in the union update rewrite (oxgraph-core). Resolved 2026-11-11: keep the rewrite.** A `WITH <g>` operation
   (no `USING`) is left as written, so while the scratch graph exists its `GRAPH ?x` could bind the scratch graph. It now gets
   `USING <g>` and a `USING NAMED` for every IRI-named graph, which is its own dataset without the scratch graph. The first
   recommendation (a scratch graph per operation) was dropped: it needs one `Store.update` call per operation, and Oxigraph
   applies a request atomically only as one call. Blank-node-named graphs are not visible to such an operation while the
   scratch graph exists (`USING NAMED` takes only IRIs). Regression tests are in `test_hunt_oxgraph_core.py`.
2. **`PT.5S` / `PT1.S` durations (shacl-values). Resolved: keep accepting them.** The fix would reject a seconds group with no digits on one side of the
   point. Two existing tests pin the opposite on purpose (they cite the XSD grammar's `unsignedDecimalPtNumeral`, and
   Oxigraph agrees). Recommended: keep accepting them. Reverted, nothing changed.
3. **Prefix direction (workbench-contract #7). Resolved 2026-11-11: keep it strict.** The workbench editor will alert the user to
   these problems and offer to add the known file-level prefixes to the shapes' SPARQL (logged in `graph-workbench/docs/deferred.md`). `sparql_query_problems()` now agrees with the engine, which resolves only
   `sh:declare` / `sh:prefixes` and does no ambient lookup. An existing test asserted the opposite and was rewritten. The
   alternative is to make the engine resolve file-bound prefixes.
4. **Manchester non-spec row 32.** Rewritten in `non-spec-behaviour.md` as resolved (a pick, pending your confirmation):
   `one-member-disjointclasses` and `empty-language-tag` are now rejected as the grammar requires
   (`STRICT_BY_GRAMMAR` in `test_mc_negative.py`).
5. **`test_matches_plain_rdflib`** (above): approved, now xfail.

## Open items (not fixed)

- `srl_validate` still reports "conforms" for some damaged `srl:` trees (a missing list tail, a missing
  `rdf:type sqe:TripleTerm`), and some of them silently decode to a different rule set. Decoding now raises
  `SRLDecodeError` rather than a raw error, but the shapes were not strengthened.
- `manchester_parse_to_tree(graph=<pyoxigraph.Store>)` fails because a Store has no `.bind`; the docstring promises Store
  support. A second parse into the same graph now raises `ValueError`.
- A variable name above U+FFFF is accepted by the SPARQL grammar but rejected by pyoxigraph in query text; SRL now refuses it at
  parse time with a clear error (`unsupported_variable_name`).
- A blank node passed through `IF`/`COALESCE` in an SRL `SET` still follows the engine's `substitutions=` behaviour.
- No nightly SHACL benchmark guard: the old one imported the removed `TripleTermAdapter` and was deleted with its baseline.
  Record a new baseline on the CI runners before adding one back.
- Other recursive helpers named in the robustness report (`skolemize`, RDF/XML and pretty serialization) were not made
  iterative; only `cbd()` was reproduced.
- Some regression tests were judged from the diffs by the reviewer rather than shown failing against a reverted fix.
- `EntailmentSession` is missing from the API reference until codeKG is regenerated (parked).

## Candidates for upstream reports (nothing filed)

- **Oxigraph / pyoxigraph 0.5.13:** a SPARQL query with 5000 nested groups overflows the stack and kills the interpreter
  (raw `Store.query` crashes too; 2000 nested parentheses are fine). `isomorphic()` on a 20000-node blank-node chain
  also dies with SIGSEGV.
- **pyoxigraph 0.5.13:** a literal bound to a variable used as the subject of a triple-term pattern raises
  `RuntimeError: not a valid RDF 1.2 term`; worked around in SRL evaluation.
- **Oxigraph (feature request):** a union-default-graph option for `Store.update`, as `query()` has with
  `use_default_graph_as_union`; it would make the update rewrite and its scratch graph unnecessary.
- **rdflib 7.6.0:** `OPTIONAL { ... FILTER(?x != ?x) }` drops the row; `CONSTRUCT` emits a triple with a literal subject.

## Behaviour changes worth knowing

- `:q +5` is now read as a path `:q` followed by the signed number `+5` in the shared SPARQL parser (the SPARQL tokenizer
  rule); it changes SPARQL parsing as well as SRL. W3C syntax and parse conformance still pass.
- `sh:construct` rules are now checked like `sh:select`/`sh:ask`: `SERVICE` is rejected (it would send a request from the
  shapes graph); `MINUS`, `VALUES` and assignment of a pre-bound variable are rejected for shape rules only, because a
  global rule has no pre-binding.
- `check_query(prepare=True)` no longer runs a query containing `SERVICE`.
- `StarQuery.run()` rejects unknown overrides with `TypeError`.
- Removed: `benchmarks-graph/bench_scaling.py` (it measured backends that no longer exist), the "Integration tests" CI step
  (it selected no tests and exited 5), and the unused `STARLAYER_RUN_ENGINE_ABORT_TESTS` mentions.
- The guides no longer describe `StarLayerGraph` as a working name for itself (left from a global rename of `OxGraph`),
  no longer say query-time entailment is unavailable, and no longer mention pySHACL delegation.
