User Guide

StarLayer

StarLayer extends rdflib with RDF 1.2 features and adds SHACL 1.2 validation and rule execution in a form that fits the familiar rdflib and pyshacl developer flow. This guide assumes you already know RDF, rdflib, and SHACL basics and focuses on the incremental capabilities that matter most in practice.

This project is a research-grade RDF 1.2 stack and remains under active development. The public install is the full starlayer package, but the repo is still organized internally into graph, SPARQL, and SHACL layers.

1. Start with a normal rdflib-like graph

The core graph layer is a drop-in style RDF 1.2 graph. You still work with an rdflib-like API, but you can represent RDF 1.2 values such as triple terms and reified statements without leaving the Python object model. 

from rdflib import Literal, Namespace
from starlayergraph.graph.starlayer_graph import StarLayerGraph

EX = Namespace("http://example.org/")

g = StarLayerGraph()

g.add((EX.alice, EX.name, Literal("Alice")))
g.add((EX.alice, EX.knows, EX.bob))

g.add((EX.alice, EX.says, (EX.bob, EX.knows, EX.carol)))

print(list(g.triples((None, EX.name, None))))
print((EX.alice, EX.says, (EX.bob, EX.knows, EX.carol)) in g)

The important difference from plain rdflib is that a triple can be used as an object value. This is the RDF 1.2-style triple-term workflow and it is available without rewriting the rest of the application around a new graph type.

Reification and annotation folding

g = StarLayerGraph()
g.parse(
    data="""
        @prefix ex: <http://example.org/> .
        ex:alice ex:claims ex:bob .
        ex:alice ex:claims ex:carol {| ex:source ex:wiki |} .
    """,
    format="turtle12",
)

for s, p, o in g:
    print(s, p, o)

2. Query using the SPARQL layer

The SPARQL layer integrates with the graph layer and handles RDF 1.2 constructs while still letting you work with familiar SPARQL evaluation patterns. This is the natural next step after the graph layer. 

from rdflib import Namespace
from starlayergraph.graph.starlayer_graph import StarLayerGraph

EX = Namespace("http://example.org/")

g = StarLayerGraph()
g.parse(
    data="""
        @prefix ex: <http://example.org/> .
        ex:alice ex:knows ex:bob .
        ex:alice ex:knows ex:carol .
    """,
    format="turtle",
)

rows = g.query("""
    PREFIX ex: <http://example.org/>
    SELECT ?person WHERE {
        ex:alice ex:knows ?person .
    }
""")

for row in rows:
    print(row.person)

Triple-term-aware query pattern

g = StarLayerGraph()
g.parse(
    data="""
        @prefix ex: <http://example.org/> .
        ex:alice ex:claims <<( ex:bob ex:knows ex:carol )>> .
    """,
    format="turtle12",
)

rows = g.query("""
    PREFIX ex: <http://example.org/>
    SELECT ?stmt WHERE {
        ?s ex:claims ?stmt .
        FILTER( isTripleTerm(?stmt) )
    }
""")

for row in rows:
    print(row.stmt)

3. Validate with SHACL 1.2

Once your graph works, the next step is checking it against a shapes graph. The validator is designed to sit on top of a normal rdflib/pyshacl workflow, while extending it for RDF 1.2 values and richer SHACL behavior. 

from rdflib import Literal, Namespace
from starlayergraph.graph.starlayer_graph import StarLayerGraph
from starshacl import StarShaclValidator

EX = Namespace("http://example.org/")
SH = Namespace("http://www.w3.org/ns/shacl#")
XSD = Namespace("http://www.w3.org/2001/XMLSchema#")

data = StarLayerGraph()
data.add((EX.alice, EX.age, Literal(30)))

shapes = StarLayerGraph()
shapes.parse(data=f"""
    @prefix ex: <http://example.org/> .
    @prefix sh: <http://www.w3.org/ns/shacl#> .
    @prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

    ex:PersonShape a sh:NodeShape ;
      sh:targetClass ex:Person ;
      sh:property [
        sh:path ex:age ;
        sh:minCount 1 ;
        sh:datatype xsd:integer ;
      ] .

    ex:alice a ex:Person .
""", format="turtle")

validator = StarShaclValidator()
result = validator.validate(data_graph=data, shacl_graph=shapes)
print(result.conforms)
print(result.report_text)

Triple terms in validation

data = StarLayerGraph()
data.parse(
    data="""
        @prefix ex: <http://example.org/> .
        ex:alice ex:claims <<( ex:bob ex:knows ex:carol )>> .
    """,
    format="turtle12",
)

shapes = StarLayerGraph()
shapes.parse(
    data="""
        @prefix ex: <http://example.org/> .
        @prefix sh: <http://www.w3.org/ns/shacl#> .

        ex:ClaimShape a sh:NodeShape ;
          sh:targetSubjectsOf ex:claims ;
          sh:property [
            sh:path ex:claims ;
            sh:minCount 1 ;
          ] .
    """,
    format="turtle",
)

result = StarShaclValidator().validate(data_graph=data, shacl_graph=shapes)
print(result.conforms)

4. Apply SHACL rules

In addition to validation, the SHACL layer supports rule execution. This is a useful pattern when your graph should be inferred or expanded from shape-driven rules rather than only checked for conformance. 

from rdflib import Namespace
from starlayergraph.graph.starlayer_graph import StarLayerGraph
from starshacl import StarShaclValidator

EX = Namespace("http://example.org/")

data = StarLayerGraph()
data.parse(
    data="""
        @prefix ex: <http://example.org/> .
        ex:alice a ex:Person .
    """,
    format="turtle",
)

shapes = StarLayerGraph()
shapes.parse(
    data="""
        @prefix ex: <http://example.org/> .
        @prefix sh: <http://www.w3.org/ns/shacl#> .

        ex:PersonRule a sh:NodeShape ;
          sh:targetClass ex:Person ;
          sh:rule [
            a sh:TripleRule ;
            sh:subject sh:this ;
            sh:predicate ex:inferred ;
            sh:object ex:yes ;
          ] .
    """,
    format="turtle",
)

validator = StarShaclValidator()
result = validator.apply_rules(data_graph=data, shacl_graph=shapes)

print((EX.alice, EX.inferred, EX.yes) in result.data_graph)
print(result.conforms)

When to use rule execution

  • Generate derived triples rather than only report violations.
  • Apply graph-transforming rules alongside validation.
  • Work with SHACL 1.2 patterns where a rule-based workflow is more natural than a pure validation-only pass.

5. Use the adapter for triple-term-heavy workflows

Some SHACL workloads carry triple terms through multiple evaluation layers. The adapter layer normalizes this process so you can keep using real StarLayer graph objects while interoperability remains stable. 

from starlayergraph.graph.starlayer_graph import StarLayerGraph
from starshacl import StarShaclValidator, TripleTermAdapter

adapter = TripleTermAdapter.for_starlayergraph()
validator = StarShaclValidator(adapter=adapter)

data = StarLayerGraph()
# dataset + shape setup goes here

result = validator.validate(data_graph=data, shacl_graph=data)
print(result.conforms)
